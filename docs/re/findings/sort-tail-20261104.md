## Exact menu sort pivot storage

The source retains the partition pivot in a `void*` declared before the outer loop, initializes it from the final element address, and casts that storage directly at each pivot use. The sorting network still receives an ordinary iterator copy. The comparisons, swaps, partition bounds, recursion, and shuffle state are unchanged.

This is a compiler-control fake, not evidence that the original MSL implementation used an opaque pointer. The ordinary typed-pointer forms remain at 99.372826%. A typed reference alias for the pivot also loses the gain. Moving iterator declarations outside the loop, including every order of the three partition iterators, leaves the baseline unchanged. The opaque pointer representation and its direct uses therefore matter in this compiler; declaring locals early alone is insufficient.

## Exact Sort caller alias analysis

`CPiiListFilterSort::Sort` compares at 100% with `#pragma c9x_alias_by_type on` immediately before the function and `#pragma c9x_alias_by_type reset` immediately after its body. The original caller was 96.16456%, with six scheduling differences in the argument setup for `std::sort`. The complete candidate changes only that function's percentage; every other function comparison remains unchanged.

Read-only scheduler instrumentation identifies the cause. In the block immediately after `begin()` returns, both scheduling passes add an edge from the stack store of the returned iterator to the load of `this->mSortType`. That edge delays the mode load until after the iterator store and the argument-address calculations. The target loads the mode first. The local type-based alias control removes the false stack-temporary/member dependency and reproduces every target instruction, with unchanged C++ operations and data.

This is a documented D-0016 compiler control, not recovered evidence of original build flags. It is deliberately scoped to this function: enabling the same control at the start of the translation unit changes template scheduling and regresses the sorts. `auto_restrict`, `auto_restrict_locals`, and `relax_restrict` did not resolve the dependency.

The exact candidate is `tools/local/tail-20261104/game_CPiiListFilterSort/sortaliasflags_c9x_alias_by_type_on_caller/`, containing source, object, compiler log, and comparison JSON. The baseline dependency graph is `sortagent_schedtrace.txt` in that unit's scratch directory; the read-only hook is `tools/local/tail-20261104/sort_sched_hook.js`. The hook's graph-node interpretation was checked against the [CodeWarrior scheduler source](https://github.com/doldecomp/mweppc/blob/main/src/compiler/backend/Scheduler.c) and the already documented Wii/1.1 function addresses in [sprint-ra](sprint-ra.md).

## Shared-pointer sort allocation and final exact control

Read-only Frida traces of the configured Wii/1.1 compiler show that the shared-pointer comparator-reference sort colors the pivot's split node first: its degree is 37, ahead of the division constant. The comparator-value sort's corresponding degree is 36 and its coloring order already matches. That candidate is rejected.

The trace and source probes are retained under `tools/local/tail-20261104/game_CGameResult/` and `game_CPiiListFilterSort/`. The session tested constructor and iterator operator shapes, comparator wrappers, sorting-network wrapper argument orders, partition-local lifetime splits, all unused prefix/postfix increment combinations, explicit template instantiation, and scoped/global optimizer controls. These earlier probes did not make the shared-pointer reference variant exact, and no fuzzy gain was retained.

The final source-only control changes the right-hand control-block load inside `shared_ptr<T>::swap`. A local `detail::shared_ptr_deleter_common* pOtherState` is initialized from `r.s_`, reassigned through a same-type `static_cast`, and then stored to `s_`. The original left-hand temporary, pointer exchange, and final control-block store remain unchanged. `GAME_SHARED_PTR_SORT_STORAGE` scopes this form to CGameResult and CPiiListFilterSort. The ordinary sorting algorithm and iterator roles are unchanged.

This is a D-0016 compiler control. The reassignment is semantically redundant, but unlike a plain named copy it retains an early named register node for the right-hand load. Read-only graph snapshots at the simplifier entry show the precise threshold: the original reference sort's pivot has working degree 29 when first visited, exactly the allocator's 29-register cutoff, while the already exact value variant has degree 28. The surviving comparator reference supplies the extra edge. In the final candidate, three control-block loads move from late anonymous temporaries to early named nodes. Their removal before the pivot lowers its first-visit degree to 26 in the reference instance and 25 in the value instance. The original instruction sequence and register assignment then match in both.

The graph simulator copies the compiler's graph and performs the elimination on its private JavaScript objects; it does not alter the compiler or output object. Its source is `tools/local/tail-20261104/sort_simplify_sim_hook.js`, and its before/after traces are `sortagent_simplifysimtrace.txt` and `sortagent_finalsimtrace.txt` under the CGameResult scratch directory. ## Exact CPii snapshot swap

`swap<vector<SD_PiiPersonalData::Data>>` now compares at 100% with source-only specializations in CPii.cpp. The 3052-byte function retains the original copy, assignment, allocation, cleanup, and exception paths. The final candidate changes only this function from 99.16514% to 100%; every other function comparison and the complete function-symbol set are unchanged. No shared vector header change is retained.

Three controls are needed together. The copy-constructor specialization uses separate allocation and construction helpers, with its input range held in a two-pointer aggregate. This first reproduced the 99.48886% candidate and made the copy-construction prefix through offset 0x200 exact. A specialization of the non-POD `assign` member template caches the current capacity in a one-field aggregate after computing the input distance. That improved the isolated candidate to 99.71166%, with the correct first-pointer registers in both assignment blocks. Finally, the assignment-operator specialization holds the source range in a two-pointer aggregate and initializes its fields directly from `data_` and `data_ + size_`. Combined, these give the target end-pointer register r24 and preserve the target first-pointer, capacity, allocation-result, and zero registers in both assignments.

The aggregate controls are a D-0016 fake-match technique, not evidence that the original library used these specializations. An ordinary scalar capacity cache reaches 99.63958%; using the existing `begin()` and `end()` accessors to initialize the range loses the final gain. A separate endpoint aggregate makes the endpoint register correct but moves the first pointer to r28. Both fields in one range aggregate, with direct storage expressions, are necessary for the accepted form. Full-width endpoint bitfields add instructions and were rejected.

The coordinator's first isolated source link confirms all owned functions at 100%, but the executable is 128 bytes short. Section comparison identifies a 96-byte code deficit, an 8-byte exception-table deficit, a 12-byte exception-index deficit, and a 32-byte data deficit. This is not full-unit acceptance.

The code and exception deficits identify `std::tr1::detail::is_null(...)`. The original keeps a local 84-byte copy at `0x800DD6A0`, followed by 12 bytes of alignment, while the reconstructed weak inline definition is discarded in favor of the earlier global copy at `0x80070700`. A translation-unit-scoped `static inline` declaration preserves the required local ownership. No helper instructions change.

Two identical 64-byte destructors had transposed inferred names. The original texture-animation deleter vtable at `0x803A80B8` points to `0x800E01B0`; the original callback `function_imp` vtable at `0x803A81B0` points to `0x800E0170`. These pointers establish the identities even though both instruction bodies compare exactly. The natural source order agrees with the corrected identities.

The data also exposes a probable original translation-unit boundary. The original contains the same 55-byte length-error type string twice, at `0x803A876C` and `0x803A8944`. The combined reconstructed source reuses it. The second literal group starts with `vector length error` at `0x803A8930`, after CPii's final RTTI and exception strings, and contains the CPiiBox deleter and missing-callback exception metadata. The corresponding code boundary is `0x800E0200`, immediately after CPii's destructor-adjustment thunk. This supports separately compiling CPii and CPiiBox rather than forcing a combined unit's text and data order.

The private split candidates are `piisplit_model/CPii.cpp` and `piisplit_box/CPiiBox.cpp`, with their independently compiled objects alongside them. Together they emit all 72 owned functions in the target order after the destructor identity correction, preserve all function comparisons, and match all 60 exception records including cleanup relocations. The CPii source retains local `is_null`, places its motion-file helpers after `ApplyMotionInfo`, and defers the callback destructor definition until after `OnLeaveWorld`. The CPiiBox source owns the snapshot specializations and discarded callback-error factory.

The first split native link restores the exact `.text`, `extab`, and `extabindex` sizes, leaving only 32 extra bytes in the final `.data` output. ## Traps

- `always_inline` on an auxiliary helper does not override this caller's `dont_inline` scope. Direct disassembly still contains a call to the helper, so such a probe does not test the intended inline lifetime change.
- A pragma surrounding a template definition and reset before first use does not control its eventual instantiated optimization in these experiments. Setting the same pragma before the translation unit affects code; appending it after all uses does not. Compare the generated function before drawing conclusions from a template-local flag sweep.
- Opaque pointer storage can change the register graph while every operation remains identical. Typed pointers and typed reference aliases are not equivalent compiler controls. Keep any use of this technique local and record exact object comparisons and final-link evidence separately.
- A range aggregate is not interchangeable with two scalar locals or accessor results in the CPii snapshot assignment. Direct `data_` and `data_ + size_` expressions in the same aggregate preserve the exact allocation order; the accessor form and a separate endpoint aggregate do not. The source-only member specializations isolate this compiler control without changing generic vector behavior.
- When a combined source has exact functions but reuses a literal that appears twice in adjacent original metadata groups, inspect translation-unit ownership before forcing data order. CPii/CPiiBox's repeated exception string and matching code/RTTI boundary led to a natural split verified against the complete frozen executable.
- A high-degree pivot can be repaired by an earlier temporary elsewhere in its live range. For the shared-pointer sorts, naming the swap's right-hand control-block load and retaining it through a same-type reassignment removes late interference before the pivot's first simplifier visit. Naming the other pointer load does not give the same result. Trace the actual working degree, not only the initial adjacency count.
