# F-327-5: Weak-reference lock acquisition

The original function at 0x801C95B0 is the weak_ptr<BUI>::lock consumer. Its native extent is 204 bytes. It returns an empty shared reference when the control block is absent or its strong count is zero. Otherwise it acquires a temporary shared reference while the strong count remains nonzero, copies that reference to the return value and releases the temporary. The original retains the unexpected-exception cleanup generated by the shared-reference destructor.

## Independent source evidence

An independently authored typed weak/shared-reference diagnostic was compiled with the actual BController game-profile command, Wii/1.1 and unchanged game flags. A named shared-reference result with ordinary acquisition, followed by retain through the result's control pointer, reproduces all 204 native bytes after resolving both instruction relocations. The paired targets are shared_ptr_deleter_common::release at 0x8034D84C and __unexpected at 0x80341A60. All forty retained exception-table bytes also equal the original at 0x8003C2C8. The original twelve-byte index at 0x8005130C supplies the native function address, extent and exception-table address. The comparison resolves targets independently and does not mask their instructions.

The diagnostic uses an ordinary named result and the established reference-count representation. No register bindings, compiler-option changes or source-byte substitution are involved. The same result is obtained by acquiring through a local control-pointer snapshot after the expired check. The complete typed smart-pointer implementation remains outside the repository; these checks do not establish a source-selected translation unit or add progress credit.

Only constructor and lock declarations were extracted from the public MSL-family interface, blob e57966d2bb1331d2b2b21137c9bc389e90c6c573 in KooShnoo/pokemon-rumble. That declaration evidence includes the shared/weak converting constructors, the ordinary private element-pointer/control-pointer constructor and lock() const without an exception specification. No restricted implementation bodies were read or reused. The independently attempted private pair-constructor algorithm did not reproduce this function and is not accepted as the original algorithm.

## Reproduction and limits

The outside scripts 327-smart-variants.py and 327-audit-smart-lock.py preserve the individual compiler candidates and fully resolved comparison. The accepted diagnostic is the use_result_count candidate. Its object and machine-readable proof are preserved separately from the canonical-header proposal and from other list diagnostics. No canonical typed shared_ptr or weak_ptr header has been published. The list destructor remains eleven register-word differences from the original and continues to block complete BUI source acceptance.

## Traps

- Returning a directly constructed temporary enables return-value elimination and reduces this consumer to 108 bytes. Keeping the acquired reference in a named result preserves the original copy/release behavior. A conditional-expression variant instead grows to 296 bytes and is not accepted.
- Adding throw() to lock is unsupported by the declaration evidence and changes its exception behavior. Keep the shared-reference destructor's existing exception contract and validate the actual retained exception table.
- A correct function extent alone is insufficient. The first 204-byte acquisition candidate still had seventeen register-word differences; only the independently paired final candidate matches every instruction and retained exception byte.
