# Sprint a20: MSL container headers

## Landed changes

- **vector trivially copyable fast paths (+6 matched functions).** `include/vector` dispatches `push_back`, `push_back_realloc` and `__vec_split_buffer::construct_at_end(n, x)` on `__vec_trivial_copy<T>`: `is_POD<T>` or `(__builtin_trivial_members(T) & 7) == 7` (trivial destructor, assignment and copy constructor). `reallocate` and `move_construct_to_end` still use `is_POD<T>`, which is why the original has `++size; back() = x` in `push_back` and in the new-buffer fill, but a null-checked placement construct in `reserve`. The four `vector<SD_*::Data>::push_back` functions, `CBattleRoyalBox::ExportBattleRoyalData` and `CPii::ExportPersonalData` reach 100%.

- **Pointer lists use a two-level iterator (+33 functions in ScriptWorldObj).** `include/list` specialises `__list_imp<T*, Allocator>`. Its `iterator` and `const_iterator` derive from the `__list_deleter` iterators, copy-construct from them, and forward `operator*`, `++`, `--`, `!=`, `==` to the base bodies. `begin()` and `end()` (both const and non-const) return the derived type, so `list::begin` is a separate 0x3C function that builds a temporary from `__list_deleter::begin` and copies it (hidden return pointer), while `const_iterator` has no user copy constructor and is returned in `r3`. Lists of non-pointers (`shared_ptr`, `MTX34`, `int`, `Entry`) keep the single-level iterator; applying the wrapper to every list regressed 25 matched functions. `ScriptWorldObj` reads `rObjects` through `const std::list<BWorldObj*>&` and `const_iterator` in `PushObjectIds` and `MergeObjectIds`; the loop is `int i = 0; count = std::min(capacity - 1, size); for (; i < count; ++it, ++i)`.
- **A `__as__` placeholder may be `swap`.** The 164-byte "`list::operator=`" at `0x801CE710` swaps `size_` and the tail node and relinks empty lists. `CLayout::Load` calls `mFiles.swap(files)`; renaming the symbol to `swap__Q23std94list<...>FRQ23std94list<...>` reached 100%.
- **`tools/re/name_callees.py` renames callee placeholders (+300 functions over five passes).** An `fn_XXXXXXXX` or `dtor_XXXXXXXX` that a matched caller reaches through `bl` is renamed to the symbol the rebuilt object calls at the same place, provided every call site agrees and the target symbol size equals the rebuilt function size. Run `python tools/re/name_callees.py --placeholders --apply`, rebuild, and repeat until it reports 0 renames: each pass unlocks callers of the names it just fixed. Without `--placeholders` it also proposes renaming wrongly named library symbols; review those by hand (`KDTreeZXNode<2,9>` versus `<0,9>` and `IsSpecHidden` const-ness are source differences, not renames). Names that already exist elsewhere get `scope:local` automatically.
- **Counting 100% functions needs a stable baseline.** Other agents land source changes while you work; compare a report built from `git stash` of your change, not an old copy, or unrelated source changes show up as regressions.

- **Weak function emission order is driven by when each inline body is requested (CGloballyReusableTexBuf now Matching).** `__vec_split_buffer<T, A>::__vec_split_buffer(A&)` defined out of class (declared in the class, defined after it next to the destructor) makes the original order `~__vec_split_buffer` then `~__vec_deleter<T, A&>` for append_realloc users; an in-class constructor (the previous form) emitted the base destructor first. Defining the destructor in class or marking it `inline` also fixes CGloballyReusableTexBuf but moves the split buffer destructor ahead of the shared_ptr deleters and breaks ArgumentFormatter and ScriptItem, so it is not usable. Member declaration order inside `__vec_split_buffer` has no effect on emission order (call order does). Diagnose with the target `.fn` order from `build/wpse-v1/asm/<unit>.s` against `powerpc-eabi-nm -n` of `build/wpse-v1/src/<unit>.o`, restricted to symbols present in the target.
- **CTutorialMsg, l10n_files, ScriptCamera are not order-only.** CTutorialMsg has ITutorialMsg ct/dt order plus string and RTTI data differences, l10n_files lacks `LoadLocalizedFile`, and ScriptCamera lacks the duplicate-named `GetWorld__9BWorldObjCFv_80134360`. CDisconMsg, MapPiiTable and ScriptMessages (all functions 100% in the report) also fail the DOL check for data reasons (.data, .sdata, extab); ScriptMessages grows the DOL by 32 bytes.

## Traps

- `__builtin_trivial_members(T)` bits (Wii/1.1): 1 trivial destructor, 2 trivial assignment, 4 trivial copy constructor, 8 trivial default constructor. A class with only virtual functions reports 1.
- Keep the symbol name of `__vec_split_buffer::construct_at_end(size_type, const T&)`: dispatching with a new tag argument at the call site renames the function and regresses every unit that already matched it.
- Wrapping every list iterator, or giving `vector<T*>::iterator` a user copy constructor, regresses units that match today (25 and 4 functions respectively). Gate with the 100% count before landing.
- `static const int` locals inside `sort` are emitted into `.sdata2` once per instantiation (24 bytes of extra `.sdata2` for two sorts); turning them into an `enum` removed the data but dropped CMiniMap `sort` from 92.1% to 89.5%, so the original keeps at least one in memory. Open.
- The `if (m < i1)` inside `sort`'s `while (true)` partition loop compiles to `xor; cntlzw; slw; srwi.` in the original (a materialised bool) and to `cmplw` here; sandbox variants with a named `bool` or a copied loop did not reproduce it. Open.
- The deque "extra weak bodies" are not a function-level problem: the linker keeps only the first copy of each weak function, so CSaveManager's split lacks the `__cdeque_buf<void*>` bodies that CPlayerPii's range owns. The remaining CSaveManager gap is data (RTTI and strings), see sprint-a13.md.
