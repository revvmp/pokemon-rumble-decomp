# F-473-1: VI I2C unit and fixed timer clock

Target: `wpse-v1`, immutable `orig/wpse-v1/main.dol`, SHA-256 `ad1a5989` prefix; acceptance uses the complete frozen hash in `config/targets/wpse-v1.json`.

## Boundary and source evidence

Issue #473 combines the latter portion of `vi.c` with all of `i2c.c`. The independent I2C unit occupies `.text` `0x802C6A30`-`0x802C7344`, followed by 12 bytes of alignment before the next unit. Its initialized `__i2c_ident_flag` is a four-byte volatile unsigned word at `.sdata` `0x804B8B00`; `__i2c_ident_first` is a four-byte volatile unsigned word at `.sbss` `0x804B9678`. Both sections have four trailing alignment bytes before the next unit. No additional data or exception sections are referenced or emitted.

The source follows Petari commit `e0ab141914921726a595573dc48d3f13d0922efe`, CC0, `src/RVL_SDK/vi/i2c.c`. The local header contains only this unit's used integer types, OS entry points, and public I2C declarations. The bus-register bit operations and transfer loop agree with the original disassembly.

## Confirmed clock difference

Unmodified Petari uses `__OSBusClock` from address `0x800000F8`. Its Wii/1.0 I2C functions have sizes `0x98`, `0x3B4`, and `0x5D0`, which do not match this target. The original `WaitMicroTime` instead loads immediate `486` at `0x802C6A60`, shifts the signed elapsed 64-bit tick count by three, and calls signed 64-bit division. This is the 243 MHz bus clock divided by four and then by 125000. The same immediate occurs in the inlined waits in both transfer functions.

Using `((ticks * 8) / 486)` produces all three original sizes and identical non-relocation instruction words under Wii/1.0 with the SDK flags from F-0007: `-O4,p -inline auto,level=3 -ipa file -sdata 8 -sdata2 8`, default function alignment. Comparison used binutils 2.42-2 and the phase-2 ELF matcher; every relocation-bearing instruction word was masked. This diagnostic does not establish a full object match or linked source coverage.

## Ownership and remaining dependencies

The `vi.c` opening `OnShutdown` is at `0x802C4080`, owned by #472. Its shutdown-event switch, `VIFlush` inlining, first-call state, and retrace-counter comparison identify it against Petari. The 2009 target additionally calls the function at `0x802C8450` for events 0 and 4-6; this explains why the unmodified 2007 reference does not fully match. `__VIRetraceHandler` follows at `0x802C4220` and does match the compiled reference with relocation words masked. This issue must not invent a new `vi.c` split at the middle of that file. #472 owns its split and shared declarations; the remaining 25 functions in #473 are deferred pending that coordinated unit work.

The generated I2C source calls compiler helper `__div2i`, while the original helper at `0x803405B4` remains named `fn_803405B4`. All 14 division-call relocations in the original I2C object target that address. Its owner must establish the runtime-helper name in a separate change before this unit can link from source. No symbol outside #473's unit was renamed here. The unit stays `NonMatching`, and the original split object remains linked.

## Validation

The split-only build and frozen-manifest verification passed. The registered source compiles, and objdiff-cli 3.8.2 reports 100% for all three functions (2,308 bytes), with 100% data similarity. This score tolerates the unresolved helper name and alignment; it is not source-link acceptance. Final full-build commands are recorded in the pull request and SDK ledger. No original hashes were modified. This finding records a clock-macro difference limited to this I2C unit; it does not assert that every SDK library uses a constant bus clock.
