## What reproduced the exact functions

The two pane-name tables and the type-name table are function-local statics of the inline palette loader. As file-scope arrays the compiler hoists one `.data` base register for the whole function and shifts every register; as function-local statics each table is loaded with its own `lis`/`addi`, as in the original. The loader is an `inline` member that the initializer absorbs. Both loops store through chained assignments, the four vertex-color reads and writes are written unrolled, and the five tag colors are passed as expression temporaries to `CColorBtnTagProc::SetColor`, not through named locals.

`operator+` needs three things together: the length of the right operand computed before the left operand is inspected, the left operand's pointer and length read in one short-representation-first helper with the length declared before the pointer, and the two `replace` calls chained on the returned reference. The original does not reload the string pointer between them. Using the four-argument `replace` overload puts each iterator-tag temporary in its own inline scope, which fixes the stack slots.

`reserve` follows the library algorithm: reject lengths above `0x7FFFFFFE` by throwing `length_error`, take the size and capacity of the active representation, clamp the request to the size, round the capacity to a multiple of 16 above 11, and return when it does not change. A shrink to the short representation reuses the inline buffer. A growing allocation propagates failure, and a shrinking allocation catches it and keeps the buffer. The tail writes the data pointer and size first and the packed capacity and long flag last. Reading the capacity before the size in the long branch and ordering those three stores this way took the function from 97.86% to 97.95%.

## Remaining differences

`reserve`: the instruction stream is identical except for register numbers and stack slots in the inlined `throw length_error(...)`. In the original the first-built empty deleter temporary is at frame offset `0xC` and its by-value copy at `0x8`; the source object has them the other way round. The original also reaches the nested `what_` members through constant frame offsets and keeps one pointer register only for the final vtable store and the `__throw` argument, whereas the source object uses that register for every nested store. The literal and the array pointer take registers 28 and 27 in the original and 27 and 28 in the source object. A named exception local is much worse (75.94%). Helper functions around the allocation or the deleter, `this->` qualification, and a throw wrapper change nothing or by at most 0.02 points.

Named-layout `ApplyTextColor`: the original keeps the address of the first temporary string in a callee-saved register that holds the constructor's object pointer, then passes it to `operator+`; the source object recomputes `addi rN, r1, 0x1c` at each use. That shifts the callee-saved range by one register and the frame by 16 bytes. Neither a named local in a block, a const-reference binding, an inline helper taking `const std::string&`, an out-of-class or late-defined constructor, direct member initialization in the constructor, `this->` qualification, a four-argument `replace` in the constructor, an extra use of the address, nor an `append`-based constructor changed the output usefully; the `append` and `size()`-based constructors regress the function to 71% and 81%.

## Traps

The compiler hoists one `.data` base register when several statics of one section are used in a single function; function-local statics defeat this. Declaring the pane-name tables at file scope looked equivalent and cost twelve instructions.

The `.bss` registration object `lbl_803E65E0` was 16 bytes in the symbol map. Ending the split at `0x803E65EC` requires resizing it to 12 first, or dtk rejects the split because it ends inside a symbol.

`unitdiff.py` compares data relocations by symbol name, and the original's data symbols are `lbl_` names. The RTTI, vtable and static-storage symbols of this unit are therefore renamed to the compiler's mangled spellings in `symbols.txt`; without that, `get_deleter` shows 99.74% from one relocation name alone.


## F-55-3: original MSL string representation accessors

The recovered September 2006 CodeWarrior MSL C++ headers provide a concrete declaration contract for the string representation: `short_size()` returns `unsigned char`; `long_size()` returns a reference, with a const-reference overload; capacity and long/short state use their ordinary setters. The public `max_size()` treats byte characters and wider character types differently. These declarations are implemented against the existing proven representation without changing storage or existing operations. The reference archive identity and extraction manifest are recorded with the primary-header investigation; original SDK files remain outside the repository.

An independently reconstructed generic reserve algorithm using those accessors produces the native 560-byte char specialization at `0x8006D8B0`: all 25 actual instruction relocation targets, both cleanup targets, and the complete 68-byte exception record match. The same actual CColorConst producer retains all sixteen other native instruction bodies, including the 328-byte named-layout text-color method that earlier records listed as nonmatching. Together the preview proves all 17 instruction bodies and 3,928 bytes; data layout and full source selection are separate acceptance gates still to run.

The shared-header prerequisite adds only the accessor interface. It leaves reserve's definition in the owning CColorConst source unit. Same-base full builds compiled all 762 existing source objects: 708 are byte-identical, and every remaining object's parsed sections, symbol attributes, and raw relocations match after normalizing only numeric compiler-generated `__FUNCTION__` identity suffixes. Literal bytes and relocation destinations remain checked. The linked ELF has identical allocated payloads, and both fresh DOL builds pass the frozen artifact verifier.

The meaningful lesson is to preserve original scalar and reference return types in low-level library accessors. Substituting direct representation fields or widening the short-length return changed CodeWarrior's instruction selection even where the nominal numeric values agree. This supersedes the earlier hypothesis that only a special exception wrapper or forced temporary layout could fix reserve.
