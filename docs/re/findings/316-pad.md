# F-316-1: Complete Pad source reconstruction

Target `wpse-v1`, original `main.dol` SHA-256 `ad1a59896d3ade6b2ac35c24faa578fb3cdf8c2e2d3a9040ba8784cd033053da`. The unit spans issues #315, #316, and #317. The #315 owner approved reconstruction and preparation of the complete unit and retains publication of its header, split, and build registration.

The source boundary is `0x801B15A0`–`0x801B5308`, ending before the reset unit at `0x801B5310`. It contains 48 functions and 15,452 instruction bytes, including four functions assigned to #315, all 30 functions assigned to #316, and fourteen functions assigned to #317. The first function allocates WPAD memory through `GameMemory::AllocateMEM2`; the last function initializes and registers the global `shared_ptr<PadData>` destructor.

## Evidence and validation

CodeWarrior Wii/1.1 with the existing `cflags_game` reproduces all 48 functions. An independent ELF comparison resolves every source instruction relocation to an evidenced target address before comparing every instruction byte. The comparison also checks all 31 exception records, including destructor pointers, and their indexed function sizes. `python tools/re/unitdiff.py main/game/pad` reports 48/48 functions and 15,452/15,452 code bytes at 100%.

Separate strict comparisons reproduce the owned 416 bytes of `.data`, 40 bytes of RTTI, 136 bytes of floating constants, sixteen bytes of controller masks, and the four-byte constructor entry after resolving all associated relocations. The `.bss` and `.sbss` sizes are 32 and eight bytes. Duplicate standard-library weak definitions are emitted by the compiler and already have canonical definitions elsewhere in the executable; their source-object presence is not an additional owned range.

The real split build and the source-linked `Matching` build both pass `python configure.py`, `.venv/Scripts/ninja.exe`, and the frozen-manifest verification command with exit zero on baseline `ca14c79b`. After rebasing onto `24db281d`, including the canonical callback support from #1030, the source-linked build again passes all three commands at exact source head `364de2f3`; the independent code, exception, and owned-data comparisons also remain exact. The source-linked build reproduces the original executable hash above. No original executable bytes or replacement compiler settings are embedded in the source.

## Recovered behavior and layout

`PadData` is `0xC860` bytes. Its first 48 bytes are an `OSAlarm`, followed by signed write and read indices. It retains sixty samples across four channels for direction history, WPAD probe results and device types, and `KPADStatus`. Working and public Wii state arrays follow. Four Wii rumble objects precede per-channel activity masks, connection callbacks, the channel count, sixty four-channel `PADStatus` samples, working and public GameCube state arrays, and four GameCube rumble objects. The tail holds three minimum activity counters, their combined minimum, clamp settings, and the shutdown registration handle at `0xC858`.

The 240-byte Wii state derives from `KPADStatus`; the 68-byte GameCube state derives from `PADStatus`. Default member composition produces different aggregate copy instructions. Inheritance and individually declared button fields reproduce both the processing functions and the complete 1,844-byte public update routine.

GameCube state has the `PADStatus` base at zero, combined button fields at 12–28, four signed-short stick deltas at 32–38, unsigned-short repeat delay at 40, two `Vec2` sticks at 44 and 52, and normalized triggers at 60 and 64.

The original RTTI establishes `BRumble`, `CWiiRemoteRumble`, `CGCPadRumble`, `PadData`, and the filename `pad.cpp`. Other class and function names in this reconstruction are descriptive names based on behavior rather than recovered original spelling. `RumbleBlocker` increments both four-channel block-count arrays on construction and decrements them on destruction, stopping an active pattern whenever the resulting availability predicate is false.

`BRumble` occupies 88 bytes. Its data precedes its virtual declarations, placing the vptr at offset 80. The virtual order is destructor, const availability predicate, start, stop, and hard stop. The alarm starts at 24 and the last transition time at 72. A four-byte pattern step stores twelve-bit on milliseconds, a one-bit hard-stop boolean, three retained flag bits, twelve-bit off milliseconds, and four retained end flag bits. Only the hard-stop flag's behavior is established.

## Traps

- **A new adjacent split can expose oversized generated padding metadata.** Splitting Pad data at `0x803BF3D0` made dtk assign seven bytes to the gap at `0x803BF3C9`, although preceding `new.cpp` owns only three remaining bytes in its twenty-byte data section. The report rejected offset seventeen plus size seven. The #315 owner approved an explicit local three-byte padding symbol; the existing split end `0x803BF3CC` and separate four-byte alignment gap remain unchanged. Both the native and compiled preceding data sections remain twenty bytes, and the subsequent split and source-linked frozen-DOL gates pass.

- **A three-instruction predicate scheduling difference can identify a missing const qualifier.** The 84-byte Wii rumble predicate differed at offsets 12, 16, and 20 with a non-const member declaration. Const qualification reproduces every byte, while preserving the already exact base predicate and every caller. Wii/1.0 and Wii/1.3 do not resolve the non-const mismatch; no compiler override was adopted.
- **Small inline helper boundaries affect automatic inlining.** Keeping shake-direction extraction separate and the six-sample reversal loop in its ordinary caller reproduces the 352-byte shake function and its call from the public update routine. Splitting both stages into helpers made the outer function small enough to inline into that caller, changing the caller's floating-register saves.
- **An empty base can be observable through exception cleanup.** Removing `InterruptLock`'s empty base shortened read-delay handling from 188 to 164 bytes and rumble-stop handling from 440 to 432 bytes. Restoring the nontrivial empty-base destructor reproduces the stack-object lifetime, deleting destructors, and all exception records.
- **Do not infer callback capacity from unrelated stack stores.** The initialization callback uses the current twelve-byte `std::tr1::function<void()>`, with its inline erased callable at offset four. The previously suspected 36-byte representation confused an exception-frame anchor with the end of inline storage. No change to canonical callable capacity is required.
- **Reference-taking min/max and value-taking min/max serve different observed code.** Normalized GameCube axes use the existing value-taking `Min` and `Max` helpers. Idle-counter aggregation uses reference-taking `std::min`, reproducing its address-select instructions.
