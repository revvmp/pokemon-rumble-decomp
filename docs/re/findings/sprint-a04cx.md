## Inline-budget investigation: unsuccessful experiments

All changes below were compiled with the configured Wii/1.1 game flags, compared, and reverted. None identified the real missing inline cost.

- A transactional const-range copy loop that catches exceptions, destroys the newly constructed suffix, and rethrows changed expansion and exception tables but left `append<SlotData>` at 0%. Its frame shrank from `0x2710` to `0x1410`, still unlike the target's `0x10` frame.
- Checking `allocator::allocate(count)` against `max_size()` and throwing `bad_alloc` emitted extra branches absent from the target. The compiler did not eliminate the checks already covered by vector's length check.
- Bounding vector `max_size()` by `ptrdiff_t`'s maximum had no effect on the SaveData output.
- Combining scalar SlotData fields, a 64-bit initial flag word plus money, and removal of the status union did not trigger the required pruning. These layout hypotheses were not retained.
- Explicit in-class SlotData copy constructors with all member initializers, with and without an explicit base copy, did not change the failing append. Default construction followed by assignment made the code substantially worse.
- Constructing `__error_string` through shared-pointer `reset` or temporary assignment changed expansion substantially but did not reproduce the target. Neither was retained.
- Implementing vector copy through `assign`, `assign_range`, or a temporary deleter followed by storage swap did not reproduce the target.
- Vector assignment experiments with constant lengths, reordered locals, the existing `assign_in_place` helper, and the base range-copy overload did not produce an exact match. No shared vector change was retained.

Additional deserializer experiments: declaration order, a two-byte read helper, pointer-stepping reads, a widened count, a cached end iterator, and rereading the size from the header did not improve on the retained constant-size form.

## 2026-10-22: CGameSession and CRemoteMemory follow-up

Worked only in the current checkout and left changes uncommitted. This follow-up completes two functions, not either whole unit. CRemoteMemory source is unchanged; both units remain NonMatching. No target hashes or configuration were changed.

### Retained fixes and reusable lessons

- `CGameSession::AddMoney`: use the existing qualified `CGameSession::GetMoney()` accessor for `current`. Its inlined return gets r3, whereas reading `mMoney` directly gets r5 and changes the negative-sum register allocation. The qualified call suppresses virtual dispatch. The 204-byte function now scores 100% in both live unitdiff and the report.
- `CGameSession::Calc`: the converted range iterators already occupied the correct slots, but their stores occurred in the wrong order. Default-construct `first`, construct `last`, then assign `firstIt` to `first`. Added the ordinary default constructor and underlying-iterator assignment overload to `__implicit_convert_iterator`. This preserves the frame slots while reversing just those two stores. Swapping the two declarations instead also swaps their slots and is wrong. Calc now scores 100% in the report; live unitdiff retains only two existing static-label naming differences, with no instruction differences.

A retry-message encoder helper improved ThreadMain's live score but did not finish it or the other callers; it was removed. No additional volatile variables, assembly, optimizer pragmas, or artificial branches were retained.
