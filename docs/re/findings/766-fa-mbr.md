# F-766-1: FA boot-record validator investigation

Target: wpse-v1. The original issue owns two retained functions,612 instruction bytes, in the existing pdm_mbr.c split at0x801FD360 through0x801FD5C4. The compiler remains the established Wii/1.0 SDK configuration with default16-byte function alignment. Original hashes, source selection and compiler flags are unchanged.

The unchanged baseline passed configure --map, plain Ninja and explicit frozen executable verification. The boot-sector checker remains byte-exact at276 bytes. The master-boot-record validator remains NonMatching at336 bytes: twenty instruction words differ in the first loop's byte loads, shifts, adds and register assignments between offsets0x4C and0x9C. All remaining native instructions, function size, branch structure, returns and both partition-array stack locations agree. This is partial investigation, with no new reconstructed-source credit or issue completion.

## Expression and structure evidence

Isolated probes use the exact generated Ninja compile command, without production flag changes, and compare the complete336-byte function against the immutable DOL. Direct byte-expression permutations with independent start/count ordering reduce the disagreement to eighteen words. Readable little-endian read helpers produce the same eighteen-word lower bound. No candidate is byte-identical, and none has been applied to tracked source.

Negative probes include480 same-order expression/cast/parenthesization candidates;576 independent field permutations;91 array-type, asymmetric helper and storage candidates;192 helper argument-order, offset and return-value candidates;150 byte-local, halfword-local and accumulation candidates;120 start-expression trees;120 count-expression trees; eight partition-byte pointer/array views;64 loop-index/ABI-equivalent storage type candidates;27 ordinary for/while/do-loop variants; and12 typed partition-record views. A complete14,400-case joint search combining all24 term orders and all five binary-addition tree shapes independently for both fields also stopped at eighteen differing words; twenty equivalent condition-ordering variants did not improve that bound. Earlier symmetric helper probes that added an unwanted count-field zero store or removed the native start-field zero store are not valid336-byte comparisons and do not establish a lower bound. Compiler-version diagnostics did not recover the target; those results do not justify a compiler or flag change.

Pinned public VF implementations in [Petari](https://github.com/SMGCommunity/Petari/blob/e0ab141914921726a595573dc48d3f13d0922efe/src/RVL_SDK/vf/pdm_mbr.c), [wii-ipl](https://github.com/koopthekoopa/wii-ipl/blob/f4c09f4001c5a0b9af734ad1e3f80a54c5e5723c/libs/RevoEX/src/vf/dskmng/pdm_mbr.c), [TFP2](https://github.com/koopthekoopa/TFP2/blob/b62dfe78759133a85bf5ce451bcf496b87439b0c/src/vf/dskmng/pdm_mbr.c), [pbr-decomp](https://github.com/pbr-ret/pbr-decomp/blob/2f00145d6b48689c2d182c409828b13cdf1e55f8/libs/RVL_SDK/src/vf/pdm_mbr.c) and [mscharged-decomp](https://github.com/yannicksuter/mscharged-decomp/blob/734c3f65dcb5b59f01fda2cf4aaab8249c2da13f/src/RVL_SDK/vf/pdm_mbr.c) were inspected. Their validator has a different disk/MBR-table interface and extra operations; they do not supply this FA body. The older wii-ipl right-nested unsigned byte-read macro emits308 bytes when used as written, compared with the native336. Its all-add counterpart stays336 bytes with twenty differing words. These are reference leads, not proof of target source.

## Traps

- Comparing only changed-byte counts can hide invalid source transformations. An output helper used for both fields introduced an extra count-array zero store; a return helper removed the native start-array zero store. Require the exact native function extent and preserve both stores before interpreting a probe's difference count.
- A library-relative name does not prove an identical API revision. The public VF validator has a disk parameter and an MBR structure, while the FA target accepts a total-sector count directly. Inspect native accesses and callers before adapting that reference.
