## Traps

- A standalone objdiff percentage can disagree with the configured report even for the same object bytes. Compare hashes first, then inspect external versus local constant relocations. Here four boolean loads account for the FindAnimation discrepancy; changing input paths and line endings does not alter the object.
- Reusing one output-reference local across two inlined insertions does not preserve the same allocation for both definitions. Separate branch-local predecessor outputs resolve the second live range without additional instructions in FindAnimation. This is a local compiler control, not a general register-allocation guarantee.
- A pane-pointer key reference and its `const void* const&` storage view produce different cache behavior in the manual map lookup. The typed form removes the target's ancestor stack accesses. Use the evidenced erased-pointer key view when reproducing this container adapter.
- Replacing a member iterator adapter with a free function can merge end-address calculations even when both have the same apparent operations. The local set specialization preserves the two addresses; the free-function clone does not. Check instruction structure before attributing the residual entirely to registers.
- An apparent exception cleanup mismatch can be another identical-body name permutation. Original ArcResourceLink and FontRefLink cleanup relocations disambiguate the two allocator-reference vector deleters; correcting their names makes all 117 CLayout exception records agree.
- Function scoring concealed the wrong archive resource-root literal. The original points to `arc`, while the reconstructed source passed an empty string. Check relocation-backed contents before accepting an all-functions-exact unit.
- Identical constant bytes can conceal incorrect ownership. CLayout's two true/false pairs compare equally as data, but swapping their consumers leaves ten differing load operands. Check linked literal addresses as well as literal values.
- An unused member-pointer local can retain its constant even when its initialization emits no instructions. Two such locals left 24 bytes in CLayout's retained data and enlarged the DOL by 32 bytes. A named-false request of the same nonthrowing functions preserved code and exception records without those constants.
- Native text-section placement does not automatically reorder this compiler's exception records. The CLayout diagnostic moved LoadFromMemory's code while its extab record stayed fixed; source emission order was required for the final table order.
- In-class initialized const template members can emit in a different generation wave from equivalent out-of-class initialized definitions. CLayout's members enter the required RTTI gap, while out-of-class initializers emit after the last RTTI records. Their first address requests, not declaration order, control newest-first data emission.
- Moving RTTI ownership to a separate object does not necessarily remove its name strings from the original object's pooled data. CLayout retained all 408 duplicate name bytes even with pool_data disabled; the fragment path was rejected after the full native executable grew by 416 bytes.
