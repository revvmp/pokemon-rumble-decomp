# Sprint tC findings (long-tail units)

## Traps

- **A target that loads each `.data` string with its own `lis`/`addi` was built without data pooling.** CHPBar `SetAnimationState` referenced eight `.data` strings through one `...data.0` base register in our build and through separate `lis`/`addi` pairs in the target. `#pragma pool_data off` at file scope reproduces the target (87.5% to 100%). Look for `...data.0` relocations in the right column of unitdiff.
- **A `const char* const` table goes to a different section from the target's `.data` table.** CHPBar `sPlayerPaneNames` had to be `const char*[]` so that the strings after it in `.data` kept their offsets; until then every string reference in the unit showed as a name mismatch.
- **One dtk data label covering several strings breaks objdiff relocation pairing.** PhotoSave's `lbl_803B7D90` (0x128 bytes) holds eight strings; the target relocations used it with an addend and ours used separate symbols, so `FormatPhotoMessage` stayed at 99.93%. Splitting the label in `symbols.txt` at each string start fixed it.
- **A unit split without `.rodata` leaves its initializer in an auto unit.** CSimpleGround `LoadModel` copies a `CModel::LoadParams` initializer at 0x80354E20; adding `.rodata start:0x80354E20 end:0x80354E38` to the CShadowCamera split matched the function.
- **`sed` replacements turn `\u` into an upper-case letter.** The name `__sinit_\ut_TextWriterBase_cpp` had been written as `__sinit_T_TextWriterBase_cpp`. Edit backslash names with Python (`chr(92)`), not `sed`.
- **A named return value keeps a weak destructor in the unit.** CTitleSession's target emits `~shared_ptr<ITitleSession>` with nothing calling it. `std::tr1::shared_ptr<ITitleSession> session(new CTitleSession); return session;` emits it, and `Create` stays at 100%.
- **Plain locals take registers in assignment order, not declaration order.** CShadowCamera `CalcLightProjection` needed `f32 orthoMin, orthoMax; orthoMax = 1.0f; orthoMin = -1.0f;`: loads in the target's order and the target's registers.
- **Expression shape fixes for float code (CHPBar `CalcView`).** `x * w / 2.0f` keeps the target's operand order where `x * w * 0.5f` does not. A two-statement `speed = d / n; speed *= step;` fixes `fmuls` operand order. `Max(a, b)`/`Min` argument order picks the compare direction. When the target never spills a second `Size` temporary, reuse one `Size` local and assign its fields.

## Open

- **Several CRemoteMemory functions look partly unoptimized.** `BeginRead`, `FinishRead`, `GetPiiBox`, `PrepareWrite` and `FinishWrite` lower switches as binary searches and leave constants unfolded. `#pragma global_optimizer off` reproduces the switch trees: `GetPiiBox` rises from 65% to 86% and `FinishWrite` from 45% to 55%. It also adds a frame pointer to `BeginRead` and drops the loop strength reduction that the target keeps in `PrepareWrite`, so it was not kept. This is the same symptom F-382 reports for the NW4R draw strategies. The cause is still unknown. Sandbox checks show that `-O` levels, `-opt` sub-flags, a `volatile` selector, nested inlining and a late-defined helper all keep compare chains.
- **CTitleSession `Run` immediates depend on `.data` order.** The target emits the `shared_ptr_deleter<CUIManager>` and `<CTitleSession>` vtables and RTTI strings while compiling `Create`, before `Run`'s strings. Our build defers them to the end of the unit. All `r28` offsets in `Run` differ by 0x138 because of this.
- **ut_TextWriterBase.** `Font::GetCharStrmReader` and `~CharStrmReader` are weak copies called out of line in the target. Defining `GetCharStrmReader` inline makes our build inline it everywhere, which lowers `lyt_textBox`. The target calls `~CharStrmReader` only in `PrintToDisplayListImpl`, and our build never calls it.
