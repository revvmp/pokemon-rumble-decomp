# Sprint a13 findings

## Traps

- **Class-by-value parameters are passed as pointers to caller-made copies.** `CPostEffect(bool, shared_ptr<CFileData>)` and `BindCaptureTexture(shared_ptr<CModel>)` take their shared_ptr by value. A `const shared_ptr<T>&` parameter produced a different stack frame and temp lifetime (Create 78% to 100%, Show frame 0x20 too small). When a caller shows an extra shared_ptr copy in a temp slot and the callee never releases its argument, the parameter is by value.
- **Weak template bodies bloat the split object's `.data`/`.sdata`.** Making CSaveManager `Matching` shifted the DOL header (byte 0x37) because the object carries weak `std::__cdeque_buf<void*>` bodies, their strings and RTTI that the original object referenced as externals. Name every shared RTTI/vtable (`__RTTI__Q23std11logic_error`, `__vt__Q23std9exception`, `__vt__5ICalc`, ...) in `symbols.txt` first; sizes then converge. A unit with only a fully-owned template set (CPostEffect) linked to identical section sizes with every function not yet exact, so the bloat is specific to deque users.
- **Auto-naming template placeholders by size.** `tools` scratch script idea: for each `fn_`/`dtor_` target symbol, list source-object symbols of the same size (`powerpc-eabi-nm -S`), try each rename and keep the one that reaches 100% in unitdiff. This named 20 CPpuEngine template functions in one pass.
- **`neg/or/srwi` after a call means `bool(x)` of an int.** `result.ToInt() != 0` returned as bool materialises this; use it to tell bool-returning helpers apart.
- **`LoadLocalizedFile`'s third parameter is `u32`, not `bool`.** The 8-byte inline `LoadResourceFile(path, flags, mode, region)` forwards `mode` unchanged; naming the callee `...UlbPCc` made callers insert a bool conversion.
- **CW converts `x / 2.0f` to a different instruction order than `x * 0.5f`.** `halfRange = (far - near) / 2.0f` matched CShadowCamera; `* 0.5f` and `0.5f *` both swapped operands of `fmuls`.
- **`top *= nearClip` vs `top = tan * nearClip`** differ in operand order of `fmuls`; the compound assignment keeps the left operand first.
- **Renaming `fn_` placeholders from a source call site can mislabel them.** Pairing each target `bl fn_X` with the name the compiled source calls at the same instruction renamed 18 deque and bind helpers correctly, but `fn_800FCBD0` (really `__cdeque_buf::begin() const`, a 20-byte tail call into the const iterator constructor) was first named as a copy constructor because the implicit copy constructor sat at that call site. A renamed function that then scores 0% is the signal; read its first instructions before trusting the pairing.
- **Weak locals shared with a NonMatching neighbour block `Matching`.** ScriptCamera links only if `GetWorld__9BWorldObjCFv_80134360` (a `scope:local` weak copy inside its range) is not referenced by the original asm of ScriptCameraMotion. Flip both units together, or neither.
- **CSaveManager `.data` is +2 bytes, not a bloat of weak bodies.** After the deque helpers were named, `.data` is 2290 versus 2288 bytes and the DOL differs at section 12 (+0x20) because RTTI name strings and vtables are emitted in a different order (`function_base` comes after the CSaveManager vtable instead of right after `function_imp`). The `.text` weak-function order also differs (442 object symbols against 243 target symbols). Fix the instantiation order before setting `Matching`.
- **`__cdeque_buf(allocator)` takes `const Allocator&`.** The by-value `allocator_param` form emitted a byte copy and called `__ct__...compressed_pair` differently; a `const A&` / `A&` selector (`__cdeque_alloc_ref`) matches `__cdeque_imp(const Allocator&)`.
- **The `cdeque_imp` copy constructor is `base(alloc)`, `begin() const`, `end() const`, then a three-argument range helper.** The target passes the first iterator as a by-value copy, the second by reference, and an uninitialised allocator byte; the remaining mismatch is that `Allocator alloc;` here still calls `allocator()`, which the target omits (63% as of this note).
- **A word member initialised from a `bool` parameter is not a `bool`.** CPostEffect's `stw r4, 0xc(r3)` fixed the constructor only when `mFlag` became `int`.
- **`std::min<long>(GetCounterStopValue(id), value)` on `int` operands** reproduces the `min<l>` reference in `CStatistic::Set`; the remaining 16% is `value` being reloaded from its stack slot after `ExpandTo`, which `id += 100; ExpandTo(vec, id)` alone does not reproduce.
