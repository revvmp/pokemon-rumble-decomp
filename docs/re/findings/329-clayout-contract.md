## Ownership and inheritance

The complete CLayout source unit belongs to #329, whose first retained function is the diagnostic helper at `0x801CA880`. Its constructor is `0x801CB1C0`; the unit continues through the static initializer at `0x801D99E0–0x801D9A08`. The independent CResFont Load unit begins at `0x801D9A10`. Earlier attribution of the complete CLayout header to #327 was an ownership hypothesis and is superseded: #327 owns BUI and requests CLayout through its actual first-function owner. No source split or neighboring #330–#335 implementation is added by this prerequisite.

Native constructor stores and destructor cleanup establish a complete `0xE8` CLayout object. Vtable `0x803C0AF4` points to RTTI `0x804B83E0`, whose name at `0x804B83D8` is `CLayout`. Its base list at `0x803C0B10` identifies ICalc and ICalcDraw at offset zero. The virtual slots are destructor `0x801CC070`, Calc `0x801D62F0`, inherited CalcMtx `0x80063DC0`, inherited CalcView `0x80063DD0`, and Draw `0x801D63B0`. The declaration uses the existing canonical interfaces in that order.

## Public load contract

Wrapper `0x801CCBD0` forwards a null-terminated array of archive paths, a layout name, a shared FontMap owner by const reference, and a background boolean to `0x801CE500`. That routine iterates the archive paths, uses the boolean for file loading, and forwards the name and font owner to `0x801CF010`. The wrapper returns on zero error and builds and throws CInitializeException for nonzero errors. A void public return is inferred from this throw-or-success behavior; there is no synthesized boolean result. FindPane at `0x801D3600` traverses the SDK Layout root pane with recursive lookup enabled.

An independent #55 CColorConst source consumer compiles using the complete declaration: its local CLayout address is the native `r1+0x68`, and constructor, Load, FindPane, and destructor call interfaces agree. That consumer's complete function still differs in unrelated register allocation and coalesced helper placement; it is layout/interface evidence, not a full function match claim.

## Validation

Actual Wii/1.1 game compilation measures complete size `0xE8` and all fourteen member offsets in the table. Baseline `abfa3231d3` has 713 actual Ninja all_source objects. After expanding CLayout, all 713 compile; 711 are byte-identical. CMsgBalloon and CNoticeDisplay change only autogenerated local symbol numbering. All other sections, including relocation records and EH/data, remain byte-identical, and normalized parsed symbol attributes are identical. This preserves both existing consumers and their motion-program use.

`python configure.py --map`, `.venv/Scripts/ninja all_source`, `.venv/Scripts/ninja`, and frozen-manifest verification exit zero; the previous DOL was removed before the default build. The official landing workflow verifies the exact rebased head separately.

## Traps

The archive argument is an array of paths, and the font argument is a shared owner of a font map. A single CFileData owner or single font owner would produce a plausible-looking declaration but contradicts the native iteration, owner copies, node accesses and RTTI.

The animation map stores AnimTransform pointers, not Pane pointers. Follow the return value from SDK animation creation through the tree insertion before naming its mapped type.
