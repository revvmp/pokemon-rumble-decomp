# Sprint a17 findings

## Traps

- CModel weak functions can be identified by vtable and exception-table context: a `fn_`/`dtor_` placeholder that appears in a named `__vt__` slot or in a `DESTROYMEMBER` entry is that class member; size alone is ambiguous among identical shared_ptr/deleter instantiations.
- `CModel::TPartialAnm<0>` and `<1>` differ in code: `QueueMotion`, `AppendMotion` and `Update` for the non-main partial only test `mMotions.size() == 0`, while the main partial uses the idle check (empty, or one finished motion).
- Defining `TPartialAnm<Main>::~TPartialAnm() {}` out of line emits both destructors at the target sizes; leaving it undeclared makes `CModel::~CModel` call an undefined symbol and score 73%.
- A `CMotionProgram::SetBindFailed(bool)` inline taking `!Bind(mdl)` reproduces the `cntlzw`/`srwi.` pattern and the hoisted `get()` load in `BPartialAnm::CreateAnimObj`.
- `CPath`: a lower-bound constant on the left (`512 <= d && d < 538`) keeps two signed compares; `(int)c >= '0' && (int)c <= '9'` folds to an unsigned range. `const char` for a one-letter `std::string(&c, &c + 1)` lets CodeWarrior fold the length to 1.
- Python text-mode writes on Windows add `\r` to files that are later read by shell loops; strip them before passing names to symbol rename scripts or `symbols.txt` lines split.
- Unresolved: the nested `IsIdle()` temporaries use swapped registers (outer r6, inner r7 in the target) in `QueueMotion<1>`, `AppendMotion<1>` and `Update<1>`; moving the check into helpers, locals, ternaries or reordered operands did not change it.
- Weak-function emission order in a unit follows when the header makes CodeWarrior instantiate a member: an in-class inline body that mentions `vector()`, `shared_ptr()` or `swap` (for example `ScnMdlSimpleData() {}` and `Reset()`) instantiates them as soon as the header is parsed, so they land before every function the source requests later. Declaring those members in the header and defining them in `ScnMdlSimpleDataInline.h` (included only by the sources that use them) restored the target order of ScnMdlSimpleData.cpp.
- A duplicate-named weak function that dtk marks `scope:local` in the original object (here `max<i>` at 0x800C5C10) gets an address suffix in every other original object that references it, and a compiled unit cannot define the suffixed name. Removing `scope:local` from the symbol and renaming the other same-named copy (0x8009CE80) to `fn_8009CE80` lets a compiled caller (ScnMdlSimpleData) bind to the original definition and the DOL still verifies. Flipping CMsgBalloon itself needs more: its compiled object is 0x40 bytes shorter in `.text`, 0x20 larger in `.data` and `.sdata`.
- `basic_string<wchar_t>::assign(const basic_string&)` calls the out-of-line `replace(0, n, str)` (180 bytes, `__as__` branches to it); `<char>` inlines it with the named-tag shape. Using `replace` in `assign` takes CMsgBalloon from 434 to 435 functions at 100% while `<char>` assign in CDividedGround drops from 100% to 99.92%.
- `for (u32 i = 0; i < count; i++) { if (...) break; } if (i >= count) return false;` adds a second compare. The target shape (loop test at the bottom, `return false` right after the loop, found path skipping it) came from a `goto` past the `return false`.
- PiiSpeciesData (0x80124C80-0x80125180): 20 of 21 functions match. `IsValidPiiForm` is 94.55%: with the range check inlined as `int id = species; id >= 1U && id <= 495U` and `static_cast<u32>(form) <= N` the prologue and every arm match, but the 13-case switch tree uses signed `cmpwi` where the target uses `cmplwi`. A scratch compile shows CodeWarrior uses `cmplwi` for a short (5 case) linear switch on an unsigned value but `cmpwi` for the 13-case tree whatever the switch type, so the original tree must have come from a different source shape.
