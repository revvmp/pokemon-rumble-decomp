# Sprint a17 findings

## Traps

- CModel weak functions can be identified by vtable and exception-table context: a `fn_`/`dtor_` placeholder that appears in a named `__vt__` slot or in a `DESTROYMEMBER` entry is that class member; size alone is ambiguous among identical shared_ptr/deleter instantiations.
- `CModel::TPartialAnm<0>` and `<1>` differ in code: `QueueMotion`, `AppendMotion` and `Update` for the non-main partial only test `mMotions.size() == 0`, while the main partial uses the idle check (empty, or one finished motion).
- Defining `TPartialAnm<Main>::~TPartialAnm() {}` out of line emits both destructors at the target sizes; leaving it undeclared makes `CModel::~CModel` call an undefined symbol and score 73%.
- A `CMotionProgram::SetBindFailed(bool)` inline taking `!Bind(mdl)` reproduces the `cntlzw`/`srwi.` pattern and the hoisted `get()` load in `BPartialAnm::CreateAnimObj`.
- `CPath`: a lower-bound constant on the left (`512 <= d && d < 538`) keeps two signed compares; `(int)c >= '0' && (int)c <= '9'` folds to an unsigned range. `const char` for a one-letter `std::string(&c, &c + 1)` lets CodeWarrior fold the length to 1.
- Python text-mode writes on Windows add `\r` to files that are later read by shell loops; strip them before passing names to symbol rename scripts or `symbols.txt` lines split.
- Unresolved: the nested `IsIdle()` temporaries use swapped registers (outer r6, inner r7 in the target) in `QueueMotion<1>`, `AppendMotion<1>` and `Update<1>`; moving the check into helpers, locals, ternaries or reordered operands did not change it.
- Weak-function emission order in a unit follows when the header makes CodeWarrior instantiate a member: an in-class inline body that mentions `vector()`, `shared_ptr()` or `swap` (for example `ScnMdlSimpleData() {}` and `Reset()`) instantiates them as soon as the header is parsed, so they land before every function the source requests later. Declaring those members in the header and defining them in `ScnMdlSimpleDataInline.h` (included only by the sources that use them) restored the target order of ScnMdlSimpleData.cpp.
- A duplicate-named weak function that dtk marks `scope:local` in the original object (here `max<i>` at 0x800C5C10) gets an address suffix in every other original object that references it, and a compiled unit cannot define the suffixed name. Removing `scope:local` from the symbol and renaming the other same-named copy (0x8009CE80) to `fn_8009CE80` lets a compiled caller (ScnMdlSimpleData) bind to the original definition and the DOL still verifies. Flipping CMsgBalloon itself needs more: its compiled object is 0x40 bytes shorter in `.text`, 0x20 larger in `.data` and `.sdata`.
- `basic_string<wchar_t>::assign(const basic_string&)` calls the out-of-line `replace(0, n, str)` (180 bytes, `__as__` branches to it); `<char>` inlines it with the named-tag shape. Using `replace` in `assign` takes CMsgBalloon from 434 to 435 functions at 100% while `<char>` assign in CDividedGround drops from 100% to 99.92%.
- `for (u32 i = 0; i < count; i++) { if (...) break; } if (i >= count) return false;` adds a second compare. The target shape (loop test at the bottom, `return false` right after the loop, found path skipping it) came from a `goto` past the `return false`.
- PiiSpeciesData (0x80124C80-0x80125180): 20 of 21 functions match. `IsValidPiiForm` is 94.55%: with the range check inlined as `int id = species; id >= 1U && id <= 495U` and `static_cast<u32>(form) <= N` the prologue and every arm match, but the 13-case switch tree uses signed `cmpwi` where the target uses `cmplwi`. A scratch compile shows CodeWarrior uses `cmplwi` for a short (5 case) linear switch on an unsigned value but `cmpwi` for the 13-case tree whatever the switch type, so the original tree must have come from a different source shape.

- CMsgBalloon is 436/436 functions at 100% and its .text/.data/.sdata sizes now equal the target (Clamp<i> and IDlg RTTI symbol names, implicit `~CMsgBalloon`, inline members defined in the order Calc, SetupBattleWarp, SetupStageWarp, SetupStageModels, UpdateBalloon, RegisterWarpzone, Show, Init which reproduces the string-literal order). Still failing verify only by weak-function order (about 220 name-diff lines): the target emits the list group first, then vector, tree, then basic_string<wchar_t>; `__rf__` of shared_ptr<CMsgBalloon> sits just before `Draw` in the target but right after Create here. Pre-including `<map> <string> <vector> <list>` (after `<revolution/types.h>`) cut the difference from 262 to 222 lines; permutations of those four did not go lower.

## Traps (shift a05)

- CMiniMap `IMiniMap::Create` matches at 99.8% when the whole body is an `inline CMiniMap::Initialize` called from Create: layout loads, `5:/stage/` archive string built once and reused for both `.tpl` lookups inside their own scope block (so the strings and the first file pointer are destroyed before the `GetLayoutRect` code), the capture `TexMap` declared before the `Rect`, `GX_TF_RGB5A3`, and `background` passed to both `LoadResourceFile` and `LoadFile`. `CalcView` is still 87%: stack slot layout differs and declaration-order permutations of the four locals do not change it.
- CRemoteMemory `SetState`: the target keeps `0x42a` in a register and does not fold `0x42a | 1` or `0x200 | state`; no enumerator, local, or operand-order variant reproduced that. The target also stores `mFlags = flags & ~c` before the final OR and computes `d` before the clear. The WriteBlock switch keeps an explicit `-1` node in its tree that identical-body or merged variants drop.
- PiiSpeciesData `IsValidPiiForm`: CodeWarrior Wii/1.1 (and 1.0, 1.3, GC 3.0a3) always emits `cmpwi` for a 13-case switch tree regardless of the switch type, case suffixes, or casts; the target's `cmplwi` tree has not been reproduced. The unit's remaining objects at 0x8011D090 and 0x80125360 are outside its split, so flipping it needs only `IsValidPiiForm`.
- CMsgBalloon weak order, second pass (still NonMatching, 166 of 436 `.text` names misplaced, down from 198). Landed: an implicit `CMsgBalloon` constructor (a user-declared inline one defined after `Create` put `__rf__` of `shared_ptr<CMsgBalloon>` before the constructor's member templates), a user-declared `IMsgBalloon() {}` (puts its constructor before its destructor), `inline` on the out-of-class `__list_imp::push_back` (emits it with `RegisterWarpzone`, also helps CDividedGround and CDlgPiiList), `__list_deleter::insert` declared before the static `erase`, and the pre-includes `MSL_CPP/alloc_ptr.h`, `MSL_CPP/allocator.h`, `<memory>`, `<string>`, `<map>`, `<vector>`, `<list>`. These give the target group order list, vector, tree, `basic_string<wchar_t>`, shared_ptr family, allocator, alloc_ptr, compressed_pair, as rule 4a predicts.
- Within one class template, a member requested while its group is being emitted joins the current round only if it is declared after the member being generated; one declared earlier waits for the next round. Moving `cap()` and `alloc()` above `~__vec_deleter()` moved them out of round 1. A probe (`typedef typename __probe_t<T>::type` with a specialization lacking `type` for one argument) shows `cap<shared_ptr<CPiiTex>>` is first instantiated from `~__vec_deleter` at global scope, through the implicit `CMsgBalloon()`.
- Open: the target's round 1 interleaves `__vec_deleter` and `__vec_constructor` members by element type (`~__vec_deleter`, `clear`, `append`, `erase_tail`, `can_append`, `grow_by`, `construct_at_end` for `shared_ptr<CPiiTex>`, then the `BUILayout` deleter members and `push_back_realloc`). Minimal tests (`#pragma dont_inline on`, two class templates with a base relation, forward declarations, friend declarations, out-of-class definition order) always emit one whole class template before the other, so separate groups cannot interleave. Removing the `__vec_constructor` forward declaration and declaring `push_back_realloc` after `append_realloc` lowers CMsgBalloon to 135 but worsens CTutorialMsg (+24), BWorld and ScriptItem, so it was not landed.
- Vector `operator=` on a non-POD element: the target's copy loop is unrolled eight words at a time, which CodeWarrior does only for a `first < last` loop; the `!=` form stays rolled. A pointer-only `copy_range(const T*, const T*, T*)` overload in `include/vector` using `<` took CStatistic Save/RestoreSnapshot from 83% to 98% and the out-of-line `vector::operator=` from 83% to 98%. Remaining difference is one extra EH flag byte and register shift.
- `rOut.swap(records)` and `std::swap(rOut, records)` differ: the member form inlines the three field swaps (CPiiCollectionBox::ExportCollectionData, 8.97% to 94.5%); the free function stays a call (CPii::ExportPersonalData). A packed record whose second bitfield member is `u8 :1` reproduces the byte-wise flag clear.
- `if (n != 0)` around the non-POD `construct_at_end(n)` loop breaks other units' DOL hash and lowers Create; the guard lives somewhere else (CPiiCollectionBox::Create stays 98.16%).
- CStatistic::Get/Add: for ids -97..-1 the target branches to the `return 0` that ends the negative-id chain, not to the function's final `return 0`; none of the nested/early-return respellings tried reproduces it. GetCounterStopValue recomputes the map header address after `find` instead of reusing a cached end iterator; `iterator`, ternary and early-return spellings all stay at 79.64%.
- name_callees.py renames outside the unit break the DOL when applied blindly; restricting the applied symbols.txt changes to the unit's address range kept verify green.

## Tail wave (CDlgPiiSelector, CModel)

CDlgPiiSelector 623 to 636 of 645 functions at 100%; CDlgCollection gained one through the shared `function_base` rename. CModel stays at 151 of 158.

### Traps

- **Identical `vector<shared_ptr<T>>` clones were named for the wrong element type.** In CDlgPiiSelector the deleter clones at 0x8009AD40 to 0x8009AE10, 0x8009B180, 0x8009C310 and 0x8009E020 carried `CUIPiiListItem` names but every caller is a `CPiiPersonalData` vector (one is also called from CPlayer). Name such clones from their callers' types; renaming by address kept the DOL verified. The three `compressed_pair<char*, default_delete<char[]>>` names at 0x8009DF50 to 0x8009DFE0 are the `CUIPiiListItem` allocator pair constructors; the 11% "CompressedPairStorage" function was a misname, not a `default_delete` copy constructor.
- **A `const` pointer array leaves `.data`.** `const char* const kMotionPaneNames[]` went to `.rodata`; the target keeps it in `.data`, so it is `const char* kMotionPaneNames[]`.
- **Switching on a member after saving it allocates differently.** `int previous = mErrorState; switch (previous)` gives the target registers; `switch (mErrorState)` swaps two non-volatile registers.
- **String pool order follows source order, not instruction order.** CreateBall's model name precedes the three motion names in the target pool, so `pModelName` is assigned first in each case.
