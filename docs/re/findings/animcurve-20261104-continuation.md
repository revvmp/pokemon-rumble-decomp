# Animation-curve continuation, 2026-11-04

## Accepted semantic correction

`detail::InterpolateCurveU8` had the cubic coefficient subtraction reversed. The correct expression is `t * (t * (c0 + c1 - 2.0f))`. The previous expression used `2.0f - (c0 + c1)`. This correction follows the original executable's operand values; it is not a fake match or a claimed exact-function gain.

The frozen `orig/wpse-v1/main.dol` contains `40000000`, or `2.0f`, at virtual address `0x804BA650`, DOL file offset `0x3E65F0`. In the original `AnimCurveExecuteU8` object:

| Function offset | Original instruction | Proven value |
| --- | --- | --- |
| `0x754` | `lfs f8, lbl_804BA650` | `f8 = 2.0f` |
| `0x84C` | `fadds f7, f12, f9` | `f7 = c0 + c1` |
| `0x860` | `fsubs f7, f7, f8` | `f7 = c0 + c1 - 2.0f` |

The coefficient registers come from the two type-bit selections immediately preceding the addition. Their literals are `0.0f` at `0x804BA628` and `1.5f` at `0x804BA654`. The other polynomial constants are `3.0f` at `0x804BA64C` and `-2.0f` at `0x804BA658`. The float interpolation helper already uses the correct subtraction order.

An isolated include overlay containing only this correction preserves all eight function scores, including the three exact functions. The coordinator applied the one-line correction to `include/nw4r/ef/ef_animcurveinternal.h`; acceptance of the entire source unit remains outstanding because five executors are nonexact.

The retained source keeps the original C++ signature. It uses an explicit pointer-to-`u32`-to-pointer identity for the local command-list pointer and expands the frame calculation in the caller. The frame calculation names the infinite-loop mask and declares its fitted-period local before the arithmetic. These are documented D-0016 controls, not a claim that this spelling is original source. The pointer identity is lossless for the target's 32-bit pointer ABI.

The honest attempts included ordinary pointer copies, pointer and enum identities, a `void*` reassignment, helper wrappers at several inline depths, parameter and declaration permutations, and the available nearby compiler revisions. The allocator trace explains the remaining obstacle: the incoming pointer copy disappeared before allocation, while the fitted period retained interference degree 29 and was coloured ahead of the seed parameter. The pointer identity preserves a named local once the frame calculation is expanded. Moving the fitted-period declaration earlier changes the simplify ordering enough to assign it the target register. An intermediate candidate had only the seed/tick register pair reversed; the declaration move closes that difference without adding instructions.

This was an exact-function gain, from three to four of the eight functions. The subsequent [Child reconstruction](animcurve-child-20261104.md) raises the exact-function count to five. The unit remains `NonMatching` while U8, F32, and Rotate are unfinished. Full-build acceptance remains the coordinator's responsibility.

## Floating-point allocation: measured threshold and scalarization

The later private F32 candidate `animcurve_f32_scale_priority_31` reaches diagnostic score `99.52028`. Its 1,011 native instructions have exact floating-point operands. Remaining differences are integer register choices and one adjacent scheduling pair. This is still an unfinished candidate, not a retained or accepted match.

A read-only compiler graph hook explains the large floating-point rotation. The ordinary named interpolation time has degree 135 and is colored before the conversion bias. Constructing a one-field class from the computed time, with a conversion operator returning its `f32` member, postpones the scalarized time node until after instruction-selection temporaries. An aggregate without the converting constructor does not reproduce that behavior. A returned-class version also works if its copy constructor explicitly copies the member; the default copy path can retain unwanted stack operations.

This alone leaves the unsigned conversion bias in `f8`, while the target uses `f0`. The graph records bias degree 39. Before it is considered for simplification, eleven neighbors have already been removed: the simple interpolation weight, three cubic polynomial locals, two coefficient-selection results, and five final random-value locals. Its working degree is consequently 28, below the floating-point threshold of 32. Wrapping the simple weight `w` and cubic locals `s`, `u`, and `v` in the same converting class postpones four of those removals. The bias now has working degree 32 and survives that pass. The resulting order gives the bias `f0`, the final random A value `f1`, and interpolation time `f2`, exactly as observed in the original.

The final random B base, scale, and value declarations must precede random A's value declaration; this retains A's high-degree node through the first simplify pass. Within each random-value calculation, declaring scale before base restores their individual register order without changing the original memory-read order. Accessing the wrapped simple weight as `w.value` in its multiplication preserves the target operand order; the implicit conversion has the same arithmetic but reverses the two source register operands. These controls produce no additional native instructions. They are D-0016 candidates and require a ledger entry if retained.

The same graph-based control transfers independently to Rotate. Its investigator reports every floating-point operand exact after wrapping `w`, `s`, `u`, and `v` and using the direct member read. U8 uses its separate integer interpolation body: class construction around its simple weight, difference, and two cubic terms restores all shared floating-point constant registers, while remaining operands are still under investigation. These cross-function observations do not establish a general rule that every aggregate should be wrapped.

Reproduction uses `animcurve_fpr_graph_hook.js`, `animcurve_gpr_graph_hook.js`, `animcurve_graph_sim.py`, `animcurve_f32_time_object_0_0`, `animcurve_f32_interp_objects_15`, and `animcurve_f32_scale_priority_31`. The hooks attach to the native compiler's simplify-graph entry, copy node names, degrees, flags, and edges into JavaScript, and simulate removal outside the compiler. They never alter compiler state or output. The recorded allocator coloring order agrees with the simulation.

Current F32 integer investigation rejects simply changing the key-search local widths, adding same-type assignments, using enum/pointer identities, naming copied lower/upper bounds, and wrapping the search outputs. The exact-result node has degree 28, below the integer threshold 29; the upper-frame node has degree 98. A class-pointer result changes their later priority and fixes the lower-bound register, but leaves the upper frame and exact-result pair reversed. These rejected controls and their native comparison JSON remain in private `animcurve_f32_search_*` directories.

## Traps

- **Masked register comparisons can conceal reversed subtraction.** U8's incorrect `2.0f - (c0 + c1)` had the same opcode sequence and fuzzy score as the correct expression because both operand registers already differed. Track the values feeding noncommutative operations and verify their relocation-backed literals before treating a remaining operand difference as allocation alone.
- **An identity control depends on the surrounding inline structure.** The `void*` reassignment which retains a computed receiver elsewhere did not repair Texture's original helper-based form. After expanding the frame calculation, several pointer identities preserve the required local, and moving the fitted-period declaration closes the final register pair. Check surviving nodes and simplify order before treating an earlier negative identity experiment as universal.
- **Late cached values can alter an earlier register assignment.** F32's incorrect stride registers originate in high-degree cached values in its final random-key branch. The allocator trace, not the early instruction neighborhood, identifies those blockers. Naming the cached flags, index, and shared seed sum restores the earlier setup. This remains an unfinished source candidate; the observation does not establish a general recipe for every register rotation.
- **A high initial degree can still simplify early.** F32's conversion bias begins with degree 39 but reaches its turn with working degree 28 because eleven earlier neighbors have been removed. Delaying four proven neighbors restores the target floating-point allocation. Inspect the removal sequence and surviving graph, not just the initial degree or declaration order.
