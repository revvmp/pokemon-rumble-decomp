# Sprint r1: CodeWarrior register allocation and scheduling rules

Compiler: Wii/1.1 `mwcceppc -O4,p` with the game unit flags. Rules were derived in `-S`/objdump sandboxes on minimal reproductions and confirmed on the real units named.

## Rules

1. **One variable, one register, when a single definition reaches every use.** CodeWarrior splits a local into separate live ranges (webs) when each branch fully redefines it, and each web is coloured on its own. To make two branches share a register, give the variable one definition that reaches both branches (initialise it before the `if`, then use compound assignment in each branch). RenderUtilities `NormalizeSignedAngle`: `f32 adjusted = value;` before the `if`, `adjusted += 360.0f;` / `adjusted -= 360.0f;` inside, moved the second branch's result from f0 to f2 and flipped the unit.
2. **`x + c` and `x += c` emit different operand orders.** `adjusted = value + 360.0f` emits `fadds fD, fConst, fValue`; `adjusted = value; adjusted += 360.0f` emits `fadds fD, fValue, fConst`.
3. **`bCOND skip; b end` comes from the last operand of an `||` early return.** `if (a == 0) return; if (b < n) { ... }` emits `bge end`. `if (a == 0 || b >= n) { return; }` emits `beq end; blt body; b end`. CEffect `FreeEffectGroupID` went from 98.0% to 100%.
4. **An inline function's return value is its own variable.** It gets a separate virtual register, so it is coalesced with its operands rather than with the caller's destination. `(f32)__fabs(x)` emits `fabs f3, f0; frsp f3, f3`; MSL's `inline double fabs(double x) { return __fabs(x); }` emits `fabs f0, f0; frsp f3, f0`. ModelAim `Update` needed the MSL `fabs` (now in `include/math.h`).
5. **Registers of one class are handed out from the top down, in order of virtual-register creation.** In straight-line code with many simultaneously live values (a static initialiser), the first-created value gets the highest volatile register (f8, f7, ... f0). Inlining creates the callee's return variable at the call, before the expressions around it, so wrapping an expression in an inline function moves it up the order. ModelAim `__sinit`: `Complement(keepRate)` swapped f7/f8; the plain `1.0f - keepRate` matches, with `keepRate` still a local so that it is not folded at compile time.
6. **Compound assignment extends a live range; plain assignment starts a new one.** `x += e` keeps `x` in the node it already has. `x = x + e` (or any full assignment) opens a new live range, which is coloured on its own and usually lands in a different register. MSL `__copy_longs_rev_unaligned` needed `cps = cps + (4 - src_offset)` (new range, kept in r4 like the parameter) and `cps = (unsigned char*)lps + src_offset` for the tail loop (new range in r3). `cps += ...` merged them into one long range that was pushed up to r11. This is the same mechanism as rule 1: pick the form whose live ranges match the target's register changes.
7. **Pointer parameters reused as cursors.** MSL `mem_funcs.c` walks the parameters through cast macros (`#define cps ((unsigned char*)src)`, `#define deref_auto_inc(p) *++(p)`, with `cps = ((unsigned char*)src) - 1;`). CodeWarrior accepts casts as lvalues, and the parameter keeps its incoming register (dest in r3 in `__copy_longs_aligned`). Separate `unsigned char* dest` locals are coloured as new values (r4 here).
8. **Non-volatile registers follow declaration order.** Locals that live across calls get r31, r30, ... in the order they are declared, not the order they are first assigned. The return variable of an inlined function goes above all of the caller's locals, and loop strength-reduction temporaries go above the caller's locals among volatile registers. A caller local can never sit above an inlined function's result. FA `uhf_msc_blk_pread`: declaring `num_block, p_unit, size, result, bytes_per_sector, p_transfer, max_block, direct`, naming the product `size = num_block * bytes_per_sector`, and expanding `_uhf_msc_blk_find_unit` in place reproduces every non-volatile register (r20-r27). The search index and the strength-reduced pointer then swap (r4/r5), and no declaration order or type fixes that. The target has the inline's index (r4) but not the inline's result at the top, which none of the forms tried (static helper, early-return helper, macro, block-scoped index, inline `num_block` helper) gives. Unsolved.
9. **A negated inline `bool` materialises the compare.** `if (a < b)` and `if (!(a < b))` fold into `cmplw; bge`. A comparison returned through two inline levels with a `!` between them, such as `operator>=` defined as `!(*this < rhs)` and used as `if (m >= i1) break;`, keeps the boolean: `xor; cntlzw; slw; srwi.; beq`. A named `bool` only keeps it at a loop head (sandbox `lt2`), which is why the a20 attempt failed. This is the `std::sort` partition pattern.
10. **By-value iterator operands become variables that CSE can reuse.** `friend long operator-(iterator lhs, iterator rhs)` copies both iterators into registers. CodeWarrior then keeps `first` and `last` loaded from the loop head through the selection-sort path and reuses `first` for `m == first`, `m - first` and the recursive call argument, as the original does. Arguments are copied right to left, so `last - first` loads `first` first. The `const iterator&` member versions reload from memory at every use.
11. **Iterator arithmetic through a named result.** The generic `vector<T>::iterator::operator+(long)` must be `{ iterator result(*this); result += n; return result; }`, like the pointer specialisation, not `return iterator(mPointer + n);`. The constructor form makes `m = first + k` an inline return value and moves `m` to the top non-volatile register (rule 8).

12. **A value-initialised empty tag object is a zero store.** `erase_impl(position, Metrowerks::int2type<N>())` value-initialises the one-byte tag and emits `li rX, 0; stb rX, off(r31)`, which shifts every later frame slot. Declaring the tag (`Metrowerks::int2type<N> tag; return erase_impl(position, tag);`) emits nothing. This fixed CLayoutManager `Remove` (95.3% to 100%) and raised CFileData `ShutdownResourceFiles` and CModel `UpdateFrame`, with no regressions across the build.
13. **A parameter ranks below an inline call's result among non-volatile registers.** In ScriptPiiPropData `pprGetWazaKouka` the target keeps the engine in r31 and the popped int in r30. With the parameter used directly and `int type = pEngine->PopInt();`, the inline result takes r31. The target order needs both a `CPpuEngine* pEngine` local cast from the parameter and the pop written out (`NPpu::CValue value; pEngine->Pop(value); int type = value.ToInt();`), so that `type` is an ordinary call result declared after `pEngine`. Either change alone does nothing. The unit flipped to Matching.

14. **A class template's group follows its first declaration, so `<memory>` must declare `allocator`.** The target emits `allocator::destroy` after the `move_ptr` group, so `allocator` is declared before `move_ptr`. `include/memory` now includes `MSL_CPP/allocator.h` before `shared_ptr.h`.
15. **Member templates are instantiated at the point of use; non-template out-of-class members are deferred.** Out-of-class `tree::find_or_insert<Key>` still instantiated during `Add`. Only a non-template out-of-class member defers the chain: `map_base::erase` (keeps `allocator::destroy` and the pair destructor from following `Remove`) and the non-compact `map_base::find_or_insert_impl` overload (moves `find_leaf` and `insert_node_at` to the target rounds). Maps with a POD mapped type keep the in-class template overload, because CWaza (compact) emits `find_leaf<Ul>` right after `IncBlownEnemysCount` and l10n_files (non-compact, `const char*` values) emits `find_leaf<PCc>` and `insert_node_at` right after its caller. Only non-POD mapped types (CLayoutManager's `shared_ptr`) take the deferred overload.
16. **Inline nesting depth parity swaps frame slots.** One extra inline level between `operator[]` and `find_or_insert` swapped the `left`/`leftmost` slots and two exception-specification frames in both CLayoutManager and CWaza; two extra levels restore them. `operator[]` therefore goes through `find_or_insert` and then `find_or_insert_impl`. A forwarding `map::operator[]` also works but renames the out-of-line `map_base::operator[]` copies in six units.

17. **An inline ternary and an explicit `if` give different webs.** BWorld `CountObjects` and `FindNearestObject` matched only when the stop mask was written `u32 stopTypes = 0xFFFFFFFF; if ((type & ~ENTRY_HEAD_TYPES) == 0) { stopTypes = ENTRY_HEAD_TYPES; }` instead of the inline `GetStopTypes` ternary, with `count` declared before it. The sibling `GetObjects` still matches with the inline.
18. **`v.LenSq()` and `VEC3LenSq(&v)` colour the asm work registers differently.** In `FindNearestObject` the member form (one more inline level) gives `work0` f0 and `work1`/`work2` f1, as in the target; the free function swaps them.

### std::sort status (include/algorithm, include/vector)

The three changes above raised every `std::sort` instantiation without lowering any other function across the build (report diff; the 100% count is unchanged at 12257). CMiniMap and CWorldObjStatDisplay went from 92% to 99.84%; PiiPropData `LevelMove` from 93.7% to 99.91%; CGameResult and CPiiListFilterSort by-reference from 93.9% to 99.91%, by-value from 93.7% to 97.69%.

What remains, for whoever picks this up:
- `else if (m - first < last - m)`: the target loads `last` into r3 and puts `m - first` in r4; we swap them. Writing the comparison as `last - m > m - first`, negating it, routing it through locals, or rewriting the operator body did not help.
- The by-value-`Compare` instantiation swaps the hoisted 0x66666667 division constant (r31 in the target) with `first` (r30).
- PiiPropData `sort<vector<short>, less<short>&>` (96.33%) has a separate non-volatile ordering problem.
- Making the generic `vector<T>::iterator::operator==` by-value regressed about 30 matched functions (`__ne__` helpers, BWorld, SaveData), so it stays a `const&` member. Only the pointer specialisation's `operator==` takes copies.
- Second shift: the `m - first < last - m` swap survives every form tried in a sandbox that reproduces the function to five instructions (`scratchpad/r1/tail.sh`, `cmp.py` against the target asm): casts, `>`/`>=` rewrites, `!(...)`, subtraction forms, inline `__lt`/`__dist` helpers, locals for either difference or for `last`, swapped branches, `const&`/by-value/member variants of the pointer specialisation's `operator-`, an explicit copy constructor or assignment operator, and dropping `last` from the else-branch call. `last` always takes r4 and `m - first` r3. Plain-pointer sandboxes give the same r3 for the first difference unless `last` is passed directly as the first argument of a call, which coalesces it into r3. None of the sort units is within two functions of flipping (CMiniMap 10/20, CWorldObjStatDisplay 41/48, PiiPropData 38/48, CGameResult and CPiiListFilterSort far), so this does not block a flip.

## Sandbox method

- `scratchpad/r1/sb.sh file [compiler] [flags]` compiles with the game unit flags and disassembles with `powerpc-eabi-objdump -d -r`. `ub.py <unit source> <file> <function> [old new]` reads the unit's exact `mw_version` and `cflags` from `build.ninja`, which covers SDK and MSL units. A real unit copied into the scratch directory, with `-i src/game` and a scratch include directory placed in front, compiles in about one second. That is far faster than `unitdiff` for header experiments such as `include/algorithm`.
- To measure a header change across the project, run `ninja` and diff `build/wpse-v1/report.json` per function against a saved copy. One generic `vector::iterator::operator==` change looked harmless in its target unit but lowered 30 functions elsewhere.

## Follow-up: iterator subtraction fixes the sort comparison (2026-10-22)

The five-instruction comparison mismatch is resolved by the iterator subtraction interface, without changing `include/algorithm`. Both `vector<T>::iterator` and the pointer specialization now implement `long operator-(iterator rhs) const`. The body loads `mPointer` into a named pointer local (`T* pLeft` or `void** pLeft`) and returns `pLeft - rhs.mPointer`. This refines rule 10 above: copying both iterator operands was an intermediate improvement, not the final matching interface.

This preserves const-callability, the by-value right operand, and the original pointer-difference type. A const member directly returning `mPointer - rhs.mPointer` does not produce the same allocation: the named pointer local is necessary. A non-const member also removed the five differences in the sandbox, but was not retained. This is an independently reconstructed source form supported by generated code, not a claim to have recovered the original MSL header.

For CMiniMap's comparator-reference specialization, the target tail now loads `last` into r3 at function offset `0x378`, leaves `m - first` in r4 at `0x380`, subtracts from r3 at `0x384`, compares r4 at `0x390`, and stores r3 for the recursive call at `0x3B8`. All five previous instruction differences disappear. The companion specialization and the other vector sort users improve too.

### Reusable lesson

For this iterator subtraction mismatch, distinguish a const member's implicit `this` load from a named local pointer load. The latter changes register allocation even though the arithmetic is identical. Neither the prior blanket by-value rule nor a direct const-member expression is sufficient to reproduce this tail. Keep the right operand by value and validate both vector specializations across the full report.
