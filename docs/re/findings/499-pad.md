# F-499-1: PAD library units

Target `wpse-v1`, `main.dol`. Tools: decomp-toolkit 1.8.4, objdiff-cli 3.8.2, CodeWarrior Wii/1.0 with the F-0007 SDK flags at default alignment.

## Boundaries

The block `0x802F4C40`-`0x802F6BBC` holds two source units. `WPAD.c` begins at `0x802F6BC0`.

| Unit | `.text` | Data |
| --- | --- | --- |
| `RVL_SDK/pad/Padclamp.c` | `0x802F4C40`-`0x802F5288` | `.rodata` `0x80397DC0`-`0x80397DD8`; `.sdata2` `0x804BB4F8`-`0x804BB500` |
| `RVL_SDK/pad/Pad.c` | `0x802F5290`-`0x802F6BBC` | `.data` `0x803DCB10`-`0x803DCB68`; `.bss` `0x80477420`-`0x804774E0`; `.sdata` `0x804B8DA8`-`0x804B8DC8`; `.sbss` `0x804B9A20`-`0x804B9A50` |

`Padclamp.c` is the newer clamp unit: besides `PADClamp` and `PADClampCircle` it has `PADClamp2`, `PADClampCircle2` and `PADClampTrigger`, which pick one of two `.rodata` regions by clamp type. The older 2006 region values survive only as immediates in `PADClamp` and `PADClampCircle`; that region object is dead-stripped. `ClampCircle` calls double `sqrt` through an inline `sqrtf`, added to `include/math.h`.

`Pad.c` is the "Feb 27 2009 10:04:43 (0x4302_145)" build. zeldaret/tp's `libs/revolution/src/pad/Pad.c` (CC0) under its `SDK_AUG2010` release configuration reproduces it; the 2009 build checks for SI idle in `PADRead`, not in `SPEC2_MakeStatus`. Kept functions: 16 of the file plus `__PADDisableRecalibration`. `PADEnable`, `PADDisable`, `DoReset`, `PADSetSpec`, `PADSync` and `ClampS8`/`ClampU8` are inlined; the remaining public functions are dead-stripped.

## Result

Both units compare at 100% for every section and are linked as `Matching`. The full DOL verifies.

## Traps

- **Release assertions still count toward CodeWarrior's auto-inline limit.** With plain bodies, `PADReset` and `PADRecalibrate` were inlined into `PADInit`, `PADRead` and `OnShutdown`. One `ASSERTMSG` statement that expands to `((void)0)` in each body keeps them out of line, as in the target. When a target calls a small function the rebuild inlines, look for the original's compiled-out asserts.
- **An unused function-static still takes `.bss`.** The 0x30 bytes at `0x80477470` are `SPEC2_MakeStatus`'s `pre_status`, which no code references. Without the declaration, `PADRead`'s `pre_status` moves down 0x30.
- **Absolute-address variables enable load hoisting.** Reading `0x800030E0` through a pointer cast reloads it after every `CmdProbeDevice` store in `PADInit`. Declaring `u16 __OSWirelessPadFixMode : 0x800030E0;` gives the single load the target has.
