# F-464-3: OS.c unit boundaries and partial reconstruction

Target `wpse-v1`, `main.dol`. Tools: decomp-toolkit 1.8.4, objdiff-cli 3.8.2, CodeWarrior Wii/1.0 with the F-0007 SDK flags at default alignment.

## Boundaries

`RVL_SDK/os/OS.c` covers `.text` `0x802B1A10`-`0x802B2F50`, `.data` `0x803C72B8`-`0x803C7760`, `.bss` `0x80452520`-`0x80452590`, `.sdata` `0x804B8A28`-`0x804B8A58`, `.sbss` `0x804B9440`-`0x804B9488` and `.sdata2` `0x804BB228`-`0x804BB230`. `OSAlarm.c` begins at `0x802B2F50`. With these splits and the unit built from the original bytes, the full DOL verifies.

The 23 kept functions run from `__OSFPRInit` to `OSGetAppType`. The tail adds three functions absent from Petari: `__OSGetDIConfig` (`0x802B2E80`), `OSGetAppGamename` (`0x802B2EA0`) and `OSGetAppType` (`0x802B2F30`). `OSGetAppGamename` copies four bytes from `0x80000000`, or from `AppGameNameForSysMenu` when `OSGetAppType` reports the system menu, into the five-byte `GameNameBuffer`.

## Reference source

xbret/xenoblade (CC0) carries the same RVL_SDK build, "Feb 27 2009 (0x4302_145)", and its `OS.c` reproduces this target's static order, panic lines 1153, 1171 and 1236, the `CheckFirmare` fatal-error path and the `GetAppType`/`__OSRegisterVersion` helpers. Petari's `OS.c` gives the older structure. Data order follows xenoblade: `.bss` `__OSRebootParams`, `DriveInfo`, `DriveBlock`; `.sbss` from `__OSStartTime` to `__OSInIPL` with `__OSIsGcam` weak.

## Result

Every data section except `.data` compares at 100%. `.text` is 97.06%: 19 of 23 functions are at 100%.

| Function | Score | Remaining difference |
| --- | --- | --- |
| `ReportOSInfo` | 99.35% | String operands only; dtk merges the `.data` literals starting at `0x803C72FD` into one object |
| `OSExceptionInit` | 99.81% | String operands only, as above |
| `InquiryCallback` | 92.67% | The target emits `beq case0; b default` for the two-way `switch (block->state)`; the rebuild emits `bne` |
| `OSInit` | 89.31% | The same switch shape in inlined `CheckTargets` (`beq`; `bge`; `b`); `BootInfo` reuse in the BI2 and MEM1 arena paths; inlined `CheckFirmare` keeps the `OSIOSRev` stores (frame `0x30`) yet compares `0x80003140 & 0xFFFFFF` directly |

None of Wii/1.0, 1.1, 1.3, 1.5 or 1.7 changes the result; GC/3.0a3 and 3.0a5.2 are worse. Removing `-ipa file`, a volatile switch operand, xenoblade's `__OSGetIOSRev` operand order and separate arena variables also had no effect. The unit stays `NonMatching`.

## Traps

- **Only xenoblade has this exact SDK build.** Petari and wii-ipl `OS.c` lack the 2009 tail functions and the `CheckFirmare` path, and their static order changes `.sbss`. Start from xbret/xenoblade for any RVL_SDK unit in this game.
- **`OSInterrupt.h` conflicts with `os.h`.** Including both redefines `OS_INTERRUPTMASK`; include `os.h` and `os/OSThread.h` before `ipc.h` users and omit `OSInterrupt.h`.
