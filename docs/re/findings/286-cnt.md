# F-286-1: CNT boundary and initial reconstruction

Target: `wpse-v1`, frozen `orig/wpse-v1/main.dol`. Issue: #286.

The CNT block is `.text` `0x801778F0`–`0x80178530`, including four bytes of trailing alignment after the last function. The adjacent function belongs to HBM. Its related data is `.rodata` `0x803667C8`–`0x80366A40`, `.data` `0x803B9E60`–`0x803B9FF0`, `.sdata` `0x804B80F0`–`0x804B80F8`, and `.sbss` `0x804B9100`–`0x804B9108`. These ranges form the initial `RVL_SDK/cnt/cnt.c` split; the exact historical filename is inferred from the library name.

Evidence comes from dtk 1.8.4's split assembly and relocations, and binutils 2.42-2 `powerpc-eabi-objdump -dr` and `-s` on the linked ELF. The `.data` range starts with the CNT build banner, February 27 2009 10:05:46, compiler tag `0x4302_145`. It contains CNT initialization/open diagnostics and ES error diagnostics. The following bytes at `0x803B9FF0` start `homebutton::FrameController`. The read-only region contains the 79-pair error conversion table referenced by `0x80177D20`. The small-data region contains the banner pointer and `/./`; the small-BSS region contains the initialization flag and padding. No additional section ownership is asserted.

| Address | Name | Evidence |
| --- | --- | --- |
| `0x801778F0` | `CNTInit` | One-time ESP initialization, interrupt-protected initialization flag, CNT version registration |
| `0x80177940` | `CNTShutdown` | Tail call to `ESP_CloseLib` |
| `0x80178000` | `CNTReleaseHandle` | Frees NAND archive storage, closes the ESP content descriptor; DVD handles require no release |
| `0x80178070` | `CNTOpen` | Embedded diagnostic names the function; NAND and DVD opening branches |
| `0x801784A0` | `CNTGetLength` | Selects NAND length at offset 8 or DVD length at offset `0x34` from type byte at `0x40` |
| `0x801784D0` | `CNTClose` | NAND success; DVD close result conversion |

Names agree with the public [Rock Band 3 CNT interface](https://github.com/DarkRTA/rb3/blob/b9dfa78b64e9120b622024687b3f27b4faed700d/src/sdk/RVL_SDK/revolution/cnt/cnt.h). That interface was consulted as naming corroboration only; no third-party implementation was copied. The C source was independently written from this executable's behavior.

Do not import all signatures from that header unchanged: it declares a three-argument `CNTRead`, while the read routine at `0x801783B0` demonstrably consumes a fourth argument in `r6`, adding it to the saved NAND or DVD read offset. Its precise original API name remains unestablished. The names of neighboring functions do not prove that this is the same SDK revision or interface.

`CNTInit`, `CNTShutdown`, and `CNTGetLength` have source implementations. Wii/1.0 using the existing base flags and default function alignment produces their observed instruction sequences. objdiff-cli 3.8.2 reports all three at 100%, with 120 matched code bytes out of 3,068 and 3 matched functions out of 12 in `main/RVL_SDK/cnt/cnt`. The unit remains `NonMatching`: nine functions and the complete associated data still need reconstruction. Consequently all CNT code still links from the original split object, and this work claims no new linked source coverage.

The `CNTFileInfo` union has a NAND handle pointer at 0, start offset at 4, length at 8, and read offset at `0xC`. Its DVD representation includes a command block occupying `0x30` bytes, start offset at `0x30`, length at `0x34`, callback storage at `0x38`, and read offset at `0x3C`. The common type byte is at `0x40`; 32-bit member alignment yields total size `0x44`. Accesses in `CNTOpen`, the read function at `0x801783B0`, and `CNTGetLength` establish the used offsets. Command-block internals and the callback signature remain opaque because this source does not access them. The handle remains forward-declared.

Remaining work: reconstruct the NAND handle initializer, DVD path lookup, ES error conversion, DVD path formatting, handle initialization wrapper, handle release, open, read, and close. Preserve the full original fallback until all functions and data pass exact full-link verification. The three implemented functions alone cannot justify marking the unit `Matching`.

Validation: `python configure.py`, `.venv/Scripts/ninja`, and `python tools/verify/verify.py verify --manifest config/targets/wpse-v1.json --reference-dir orig/wpse-v1 --build-dir build/wpse-v1` each exit 0. The full DOL passes both the existing build hash check and frozen-manifest SHA-256/direct byte verification. The split-only build passed before source registration, and the registered NonMatching build passed again afterward. Existing unrelated exception-table decoding warnings remain unchanged.

## F-286-2: Handle release, offset reads, and file close

The continuation implements three more functions independently from target disassembly: `CNTReleaseHandle` at `0x80178000`, `CNTReadAt` at `0x801783B0`, and `CNTClose` at `0x801784D0`. `CNTReadAt` is a descriptive name, not a recovered original spelling; the fourth parameter and seek-before-read behavior make its offset explicit. The helper at `0x80177D20` is given the descriptive name `contentConvertErrorCode`. Its implementation remains outstanding.

The NAND handle stores archive allocation start at 0, descriptor at `0x1C`, allocator at `0x20`, and its type at `0x24`. The intermediate 24 bytes remain opaque archive metadata. Its union also describes the DVD index, root directory and current directory at offsets 0, 4, and 8, corroborated by the existing DVD path routines and public interface. The handle size is `0x28`, including alignment. This header is still used only by CNT.

Release frees the archive before closing the content descriptor and converting its result. DVD release returns success without a close. File close returns success for NAND and maps a false DVD close result to `-5005`; unsupported types return `-5063` in both routines. NAND offset reads reject negative positions or positions greater than the member length with `-5009`, seek from the content start, then read and convert errors. DVD reads use priority 2 and add the saved read offset; `-3` maps to `-5014` and other negative results to `-5003`. The routine does not update either saved read offset.

The following external dependency addresses were established from call roles. All are outside issue #286 and were deliberately left unchanged in `symbols.txt`. While this continuation was in progress, PR #550 established the ESP names; CNT now includes its shared `esp/esp.h` declarations and uses those original names. The DVD and allocator names remain descriptive dependency declarations whose original spellings have not been established in this target:

| Declaration | Target label / historical label | Observed role |
| --- | --- | --- |
| `MEMFreeToAllocator` | `fn_802E1BA0` | Allocator and block arguments, used to release the archive |
| `ESP_CloseContentFile` | `ESP_CloseContentFile` (`0x802F0BD0`) | Close content descriptor |
| `ESP_SeekContentFile` | `ESP_SeekContentFile` (`0x802F0B40`) | Seek descriptor with offset and origin |
| `ESP_ReadContentFile` | `ESP_ReadContentFile` (`0x802F0AA0`) | Read descriptor into buffer for a specified byte count |

Wii/1.0 with the established flags emits exactly the original 104 instruction bytes for release and 92 instruction bytes for close before relocation. Raw `.text` slices from the split and compiled ELF objects compare equal. Their relocation target names differ at the external calls listed above, so this is not a link-match claim. objdiff-cli 3.8.2 reports release at 99.80769%, close at 99.78261%, and read-at at 97.21667%. Read-at also has a DVD error-branch scheduling difference: the compiler hoists the default error assignment and shortens the function by four bytes. The existing init, shutdown, and length routines remain at 100%.

Six of twelve functions now have readable implementations. Six functions, associated data, external relocation naming, and the read-at branch scheduling remain outstanding. The unit stays `NonMatching`, all CNT still links from its original split object, and linked source coverage is unchanged. No new reusable trap beyond the existing CNT ABI warning emerged.

Validation for this continuation: `python configure.py`, `.venv/Scripts/ninja`, the direct `objdiff-cli diff` command against the CNT objects, and frozen-manifest verification all exit 0. The full artifact still matches the unchanged original. No reference hashes or out-of-claim symbols were changed.

## F-286-3: Complete CNT reconstruction

All twelve CNT functions and the unit's data now compile identically to the target, and `RVL_SDK/cnt/cnt.c` is `Matching` and linked. `python configure.py`, `.venv/Scripts/ninja`, and `python tools/verify/verify.py verify --manifest config/targets/wpse-v1.json --reference-dir orig/wpse-v1 --build-dir build/wpse-v1` all exit 0.

Compiler flags. CNT is built with Wii/1.0 and `cflags_sdk` (`-inline auto,level=3 -ipa file -sdata 8 -sdata2 8`), like the rest of RVL_SDK, not with `cflags_base` as F-286-1 assumed. With `cflags_base`, `entryToPathDVD` inlines its own recursion several levels deep and grows to `0x560` bytes, against `0x180` in the target, and unreferenced static functions are still emitted. With `cflags_sdk`, every function has its target size. The functions that F-286-1 and F-286-2 measured (init, shutdown, length) are identical under both flag sets.

The string pool. CodeWarrior pools all of the unit's `.data` strings into one object, `0x803B9E60`–`0x803B9FE9`. The pool keeps strings whose functions the linker later removes: `/content%d`, `Warning: CNTInitHandle(): directory '%s' is not found under '/'`, `/datatitle/%s/content%d` and `Warning: CNTInitHandleTitle(): ...`. Under `-ipa file`, a string enters the pool when the function using it is code-generated, in source order. Strings of unreferenced static functions are discarded, and strings of inlined functions enter the pool at the caller. The target order, with the `CNTOpen(): ...` message before the ES messages even though `contentConvertErrorCode` precedes `CNTOpen` in `.text`, is reproduced only when that message is first emitted by a global function defined before `contentConvertErrorCode`. That function's out-of-line copy is unreferenced and dead-stripped. The source therefore contains three global functions whose code is absent from the target: `contentInitHandleDVD`, `contentInitHandleTitleDVD` and `contentOpenDVD`. Their names are descriptive and their bodies are plausible but unverifiable, except for the strings they emit and `contentOpenDVD`'s inlined copy in `CNTOpen`. Confidence that some such global functions existed is high. Their exact bodies are unknown.

Link layout. The compiled `.text` ends at `0x8017852C`. The following auto-split HBM object at `0x80178530` was inferred with 4-byte alignment and moved up four bytes, which shifted all later code. Giving `fn_80178530` `align:16` in `symbols.txt` restores the boundary, as F-494-2 did for ENC. The `.data` and `.sbss` objects end before their split ends (`0x803B9FE9` and `0x804B9104`), and their next objects keep their original addresses.

External names added to `symbols.txt` for the link: `DVDFastOpen` (`0x802D1880`), `DVDClose` (`0x802D18F0`), `DVDReadPrio` (`0x802D1920`), `DVDGetFSTLocation` (`0x802D1A60`, a 3-instruction accessor returning `BootInfo->FSTLocation`, the name used by GameCube SDK decompilations such as Melee and TWW), `MEMAllocFromAllocator` (`0x802E1B90`) and `MEMFreeToAllocator` (`0x802E1BA0`). Their splits and sizes are unchanged.

## Traps

- **A unit's string pool can keep strings of dead-stripped functions.** Trigger: CNT `.data` contained `CNTInitHandle` and `CNTInitHandleTitle` warnings that no linked code uses, and the `CNTOpen` message sat before the ES messages despite the code order. Under `-ipa file`, strings enter the pool when their function is generated, in source order. Static unreferenced functions lose their strings, so reproduce such pools with global functions placed in source order. Evidence: F-286-3.
- **CNT needs `cflags_sdk`, not `cflags_base`.** With `cflags_base`, recursive self-inlining made `entryToPathDVD` `0x560` bytes. Evidence: F-286-3.
