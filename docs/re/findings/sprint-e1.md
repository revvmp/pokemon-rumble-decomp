# Sprint e1: emission order of weak functions and data

All rules below were measured with the game flags (`Wii/1.1`, `-O4,p -inline auto -ipa file -str reuse`) in sandbox objects and confirmed on real units. Flags (`-ipa off/function/program`, `-inline deferred`, `-str pool/nopool`, `defer_codegen`, `inline_bottom_up`) never reproduced a target order; every fix was in source or headers.

## Rules

1. **In-class and `inline` template members are instantiated when first used during parsing. Out-of-class non-`inline` members are instantiated after parsing.** This decides which round (below) a function falls into, and when the classes its body names are instantiated.
2. **Vtables and RTTI of classes created while parsing are emitted in reverse creation order, ahead of the classes created later.** For a non-template class, creation is its definition, so include order changes `.data`: `CNumericInput` needed `exception`, `shared_ptr_deleter_common`, then `logic_error`/`length_error`/`out_of_range`, then `ICalc`/`ICalcDraw`. Classes instantiated after parsing come later, in creation order.
3. **String literals of non-inline functions are pooled when the function is generated, and a shared literal (`-str reuse`) takes its place from the first generated user.** Literals of inline functions become `@STRING@<function>@n` objects. These groups come after the vtables, in reverse definition order of the inline functions, and each group is in reverse creation order. If two strong-pool literals are swapped, check which template that uses them is generated first.
4. **Deferred out-of-class template functions are grouped by class template, last-defined template first.** Within a template, the newest specialization comes first. Within a specialization, members follow the class declaration order. An overload set sits where its name is first declared: the first `replace` declaration fixed `basic_string`'s order, not the 4-argument one. Functions requested while a group is being instantiated join their group if it has not yet been emitted.
4a. **The group position of a class template is the position of its first declaration, including a forward declaration of the primary template.** A partial specialization belongs to its primary template's group. Moving a partial specialization's definition does not move its group; moving the primary's forward declaration does.
5. **A request made while another template is instantiated goes to a later round.** Each round repeats the group order. `CDisconMsg` shows `~function`, the deleter, `shared_ptr` and `move_ptr` in round 1, then `function_imp`, `function_base` and the CLayout/CFiber deleters in round 2.
6. **Inline functions referenced only from a vtable (in-class, or out-of-class with `inline`) are emitted after all strong functions, in reverse class declaration order.** Each one is followed directly by the inline functions it calls, depth first. A virtual call through `this` (`CanShow()` in `Calc`) counts as a call. `CDisconMsg` needs `inline` on `Calc`, `CanShow`, `Run`, `AdjustSuppressCount` and `IsActive`, with the class declaring `IsActive, AdjustSuppressCount, CanShow, Run, Calc, CalcMtx, CalcView, Draw`. This also places its `.data` literals after the `shared_ptr_deleter<CDisconMsg>` vtable, as in the target.
7. **A user-declared destructor is a strong function at its definition. An implicit one is generated late, with the vtable functions.**
8. **`inline` on an out-of-class template member can change code:** it got `find_leaf` inlined into `InsertString`. Check instruction matches after every `inline` change.

## Method

- `scratchpad/e1/var.py <unit> [--src file] [--flags ...] .text .data .sdata` compiles with the unit's exact flags and diffs symbol order against `build/wpse-v1/obj/<unit>.o`, keyed by name or by content for anonymous data. `sweep.py <regex> out.json [base.json]` runs it over every unit and lists the units whose order changed. Use it to gate header edits.
- For data that dtk keeps as one `lbl_` blob, `blob.py <obj> .data` prints string and relocation offsets for a side-by-side diff.
- **Find where a class or member is instantiated** by adding `typedef typename T::probe_x probe;` to its body and compiling. The error names the instantiation point: `global scope` means after parsing, a function name means during parsing.
- Flip test: set the unit to Matching, run ninja (a sha1 CHECK failure still produces the DOL), then run `c1_doldiff.py` for the differing byte runs and `c1_elfcmp.py lo hi` for the first misplaced symbol.

The `@STRING` group order needs the inline members defined in the order `Calc, SetupBattleWarp, SetupStageWarp, SetupStageModels, UpdateBalloon, RegisterWarpzone, Show, Init`; this was tested and the groups then match. Untested hypothesis: give the earlier copy a local placeholder name in `symbols.txt` and the later copy the plain global name, so each object resolves to its own.
- **`find_leaf` in tree units (MapPiiTable, CLayoutManager, l10n_files):** the target emits `insert_node_at` and `destroy` for each tree, then `allocator::destroy` and the `alloc_ptr` destructors, and only then `find_leaf` for each tree. Ours emits `find_leaf` inside the tree group. Moving its declaration after `destroy` did not move it, because the `find_leaf<Key>` overload keeps the name's earlier position. `inline` changes the code. Observed in the target: `insert_node_at` and `find_leaf` are always called from the same inlined `insert`/`find_or_insert` body, yet they land in different rounds (in CLayoutManager, `insert_node_at` is even emitted last). Requests from bodies generated at parse time go to round 1, and requests from inline bodies generated late, such as `is_null` from `Calc`, come after round 1. So the target's `find_leaf` request must come from a different body than `insert_node_at`'s. Tried without effect: `inline` with `__attribute__((noinline))` (the function stays in the round-1 tree group), moving the declaration, `inline` on `insert_one` or `insert`, and an out-of-class `map::insert`. A user-defined tuple copy constructor did not help `CDisconMsg` either.
- **ButtonMessage is not its own translation unit.** CDlgPiiList's `Setup` (0x8008ACC0) and `c_str` (0x8008D4E0) load the `basic_formatter` exception type strings at `lbl_8039DED8`, inside ButtonMessage's `.data`, and CDlgPiiList has no copy of them. String pooling does not cross objects, so ButtonMessage's functions are the head of the CDlgPiiList unit (which also declares `FindPlayerHoldingPii` itself). Flipping ButtonMessage alone fails to link with `undefined: lbl_8039DED8`. The fix is to merge the two splits and sources; CDlgPiiList is at 112/130, so this was not done yet.
- **Inlined template functions that the target still emits.** The `basic_formatter` constructor and the `shared_ptr` copy constructor are inlined everywhere in ButtonMessage, yet the target emits out-of-line copies right after their first user. Ours emits none without an explicit instantiation. An explicit instantiation of an out-of-class member is emitted at its source position, and one placed before the first use moves it to the top. Making the `basic_formatter` constructor `inline` in the header and explicitly instantiating it at the top reproduced the target order (not kept: the unit cannot flip, see above).
- **CBattleRoyalDisplay `FormatString` and `gEmptyText`.** The target emits the wide `FormatString` after the round-1 templates (`~wstring` ... `~move_ptr`) and before the implicit `~CBattleRoyalDisplay`, and `gEmptyText` (0x804B5C48, referenced by 47 units, so this unit defines it) after the late RTTI objects at the end of `.sdata`. Ours emits strong functions and variables at their definition point, before the vtable phase. Tried without effect: `inline` `FormatString` at the top or the end (it then follows `Calc`), explicit instantiation before it, `#pragma defer_codegen`, `inline_bottom_up`; `wchar_t gEmptyText[1] = L"";` under `explicit_zero_data` at the top (first in `.sdata`) or the end (after the strong pools), and without an initializer (`.sbss`).
- **Vector deferred order (ScriptCamera, CTutorialMsg).** ScriptCamera (`#pragma dont_inline on`) needs `__vec_deleter<void*>::move_construct_to_end` (both overloads) right after `reallocate`, while the same function's `__vec_deleter(allocator)` constructor and `allocate(n)` come after the deleter vtable functions. Our round-1 `__vec_deleter` group (`~__vec_deleter`, `clear`, `erase_tail`) precedes the `__vec_constructor` group because `__vec_constructor` is forward-declared first. Removing that forward declaration lets all of `reallocate`'s requests join round 1 (including the constructor and `allocate`, which the target emits later) and regresses ScriptItem, CDlgPiiSelector and others. Moving `move_construct_to_end` out of class improved CTutorialMsg and CDlgMsgWin by two each but moved ScriptCamera's copy the other way; neither change was kept. CTutorialMsg's round 1 follows the request order of the strong functions (`reallocate` from `Load`, `erase_tail` from `Clear`, `push_back_realloc` from `Show`), not the group order.
- **Script motion helpers (ScriptNullObj, ScriptCameraMotion).** The four non-extended methods differ only in the inlined `CEngine::Pop`: the target uses `lwzux` and computes the `ToString` argument after it, ours hoists `addi r4` and uses `add` plus `lwzx`. ## Traps

- Copying a header back from a scratch file after landing (the land script rebases) silently reverts other agents' newer edits to that header. Regenerate scratch variants from `git show HEAD:<path>` after every rebase.
- `git stash` is shared across worktrees (sprint-a14); keep baselines as files or commits instead.
- When a weak function has two copies in the DOL, decode a later unit's `bl` to see which copy it calls. That copy gets the global name and the other `scope:local`; for `BWorldObj::GetWorld`, ScriptWorldObj calls the ScriptCamera copy, so the earlier CDlgPiiSelector copy is the local one. The DOL verifies either way while both units are fallbacks, so only the call targets decide.
- A source-built unit can leave an `undefined: lbl_...` at link when a fallback unit points into its data. Before adding names, check whether the fallback unit has its own copy of that data: if not, the two splits are one translation unit (ButtonMessage and CDlgPiiList).
