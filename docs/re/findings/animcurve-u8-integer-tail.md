## Interpolation operands and rejected directions

After the initial integer controls, every remaining mismatch lay inside the four interpolation expansions: the start/type register choice and, in the random-input branches, the register shared by the returned byte and its source input. Every other integer path, including key search, range selection, hash generation, cached flags, and channel loops, was exact.

The intermediate `selector_u8_record_1` candidate had 56 float differences: normalized time used f12 and coefficient c0 used f13, while the target uses f13 and f12 respectively; four smoothstep products also had their operands exchanged. These are now resolved. Writing normalization as `f32 t = (f32)tick; t = t / 65536.0f;` restores all 52 exchanged time/coefficient operands. The compound assignment `t /= 65536.0f` does not produce the same allocation. Reading the existing wrapper field explicitly as `w.value * (f32)(int)(e - s)` restores the four smoothstep product operand orders. A separate scalar product with compound multiplication or an ordinary inline two-float multiply helper also works, but the field read is the smallest retained control. The remaining `CurveFloat` definitions are unchanged.

The initial private probes covered parameter/declaration order, named input and return locals, const/mutable references, narrow/wide parameter views, same-type casts, short enums, scalar classes, output forwarding, in-place interpolation, and named return joins without a complete improvement. Widening only the interpolation type to u16 reduced the remaining integer differences from 64 to 55, but changed the input cycle in another expansion. Its exact original internal parameter type is unknown. In-place interpolation removes required byte masks and changes branch/alignment bytes, so its superficially close score is not an acceptable replacement.

Scalar float declaration moves, coefficient forwarding helpers, and return-reference variations of `CurveFloat` optimize identically. Giving normalized time caller-owned output-reference storage creates a held f31 live range and increases the float mismatches from 56 to 184. Changing the float wrapper's constructor to take a const reference has a similar regression. Extra byte classes and bitfield views either introduce masked instruction changes or fail to improve operand allocation.

## Exact coupled-input controls

The final improvement couples an inline helper's scalar return with separate caller-owned output references. The control changes allocator identities while preserving the original operations and instruction positions. The first and third branches initially shared `PrepareByteInputs`: it loads the start through a `u16&` output and returns the mode as `u16`. This makes the third interpolation exact and produces the 99.85927% `sort_u8_prepared_shared` candidate, leaving 30 integer words across the first, second, and fourth branches.

For the second and fourth branches, `PrepareRandomCurveByte` copies the existing signed random value into a `u32&` output and returns the loaded mode as `u16`. The caller retains the original nested word/wide/byte conversion of that preserved start. Explicit `static_cast<u8>(start)` returns in both the interpolation equality path and case 2 force the returned byte to share the masked start instead of the wider random value. Either change alone fails; together they make both expansions exact. The intermediate `selector_u8_random_prep_1u32u16` has only 16 first-branch differences, no branch-word differences, and no floating-point or register-masked differences.

The first branch's final `PrepareBytePair` returns the end byte and writes the start through `u16&` and mode through `u8&`. ## Traps

- An ordinary pointer local can still coalesce with its destination. In this function the same-type reassignment, rather than the initializer cast, preserves the already-evidenced temporary address register.
- An instruction-sequence match is not byte identity. Intermediate U8 candidates had no register-masked or floating-point differences but still differed in integer operands. The final candidate additionally compares all raw function bytes, including branch destinations.
- Full reassignment and compound assignment are not interchangeable allocation controls. Splitting float conversion from division with `t = t / 65536.0f` fixes 52 operands here, while `t /= 65536.0f` does not.
- A mutable output reference can extend a floating-point live range substantially. Here it causes f31 allocation and widespread operand changes even though the instruction count remains 1,208.
- Two locally neutral or adverse source controls can be complementary. The explicit returned-byte casts and random-input output reference fail separately here but together recover the original byte-result allocation without extra instructions.
- Keep failed probe duplication out of the final source when it is no longer required. Once the first interpolation is corrected, its common helper can carry the random-path casts and the temporary duplicate body can be removed with exact bytes preserved.
