# Sprint w1o findings (COyaInfo)

## Traps

- **COyaInfo is its own unit, `game/COyaInfo.cpp` at 0x800ED1B0-0x800F2580.** Its `.data` starts at 0x803A9160; the `shared_ptr_deleter<CPiiPersonalData>` RTTI strings at 0x803A90B8-0x803A9160 belong to `CPiiPersonalData.cpp`, whose split now ends there. The unit is a `std::vector<std::map<int, std::tr1::weak_ptr<CPiiPersonalData> > >` of 511 buckets keyed by `id % size()`.
- **MSL map move and swap.** The vector split buffer moves a `map` by default-constructing it and swapping (`__vec_swap_move` in `include/vector`), and `tree_imp::swap` swaps the compare and the begin node separately, not the begin holder as a whole.
- **The tree's allocator constructor builds its compare from a temporary** (`begin_(Compare(rCompare))`), and the `red_black_tree` copy constructor uses that constructor. Without the temporary every inlined map copy is missing one `stb` to a stack byte and its frame is 8 to 16 bytes short.
- **A const member that searches a bucket needs a non-const map reference.** Through `const map&` CodeWarrior keeps `end_node()` in a register; the target recomputes it (FindPersonalData 88% to 100% with `const_cast`).
- **Trailing padding:** with the unit built from source, `GetPropertyRow__Fii` (PiiPropData) moved to 0x800F257C; `align:16` on it in `symbols.txt` restores 0x800F2580.
- **Open, blocks Matching:** all 26 functions match (insert_node_at differs only by the name of its local string), but the weak template order differs. Target: `insert_node_at`, `destroy`, `weak_ptr::lock`, `allocator::destroy`, `alloc_ptr` dtor, `find_leaf`, `recommend`, split buffer dtor, `construct_at_end`, `construct_at_front`, tree `copy`, `copy_children`, split buffer `allocate`, `__vec_deleter` dtor. Ours emits `find_leaf` first (the known sprint-e1 problem), reverses `alloc_ptr`/`allocator`/`lock`, and puts the split buffer functions after `copy`. Header include order (`map`, `vector`, `memory` after `revolution/types.h`) fixes only the `lock` position. A split buffer constructor that allocates moves `allocate` but is itself emitted.

## Rule: a const reference lets CodeWarrior cache loads across stores

- **Symptom:** the target reloads a pointer (`lwz rX, 0(rRef)`) after every store, even float stores, where ours loads it once; or the target loads a parameter's first word only after saving the callee-saved registers, where ours hoists it into the prologue.
- **Rule (Wii/1.1, `-O4,p`, verified with scratch compiles):** an object reached through a `const T&` (or a const pointer) is assumed not to change, so loads from it are cached across any store. An object reached through a non-const reference, pointer or by-value class parameter (passed as a pointer) is assumed to alias every store, including the register saves in the prologue, so each use reloads. Type does not matter (int, float and pointer stores all kill it); `-O` level and pragmas are not involved.
- **Fix:** make the parameter non-const. If callers pass converted temporaries (`shared_ptr<Derived>` to `shared_ptr<Base>`, or an explicit `shared_ptr<T>(x)` in a caller), take it by value: the caller-side code is identical to binding a temporary to `const&`, because CW callers build and destroy by-value class arguments. Otherwise take a non-const reference. Rename the mangled symbol (`FRCQ33...` to `FQ33...` or `FRQ33...`).
- **Applied:** `CModel::SetupMotion` (non-const `&`, 82% to 100%), `BUI::AddChild`/`RemoveChild` (by value, 74%/76% to 100%), `CUIPiiListItem` constructor (by value, 88% to 100%), `CGameSession::AddPPDToPlayerPiiBox` (by value, 93% to 100%; callers already built explicit `shared_ptr` temporaries), `CGameMap::RegisterDialog` (by value, 91% to 100%). No other function lost its match.
- **Not explained by this rule:** reloads with no intervening store, such as `CUIManager::DispatchFocusedInput` (98.6%: the flag test reloads `px` but the call reuses the first load) and `TPartialAnm<1>::QueueMotion` (reloads `mMotions.size()` after the inlined `IsReplaceable`). Changing the access form (`(*p).`, `get()->`, nested `if`, early return) did not help.
- **Same rule for `this`:** in a const member function, loads from `this` may be hoisted above the prologue's `stwu` and register saves; in a non-const one they wait until after them. `CModel::GetMotionLength` and both `CModel::FindVis` load `mModelData`'s vector during the register saves, so they are const (94% to 100%). A `const&` parameter of an inlined helper does not count: after inlining, the access path's qualifiers come from the caller's object.
- **Calling a const inline method through `shared_ptr::operator->` reloads `px`.** For a `shared_ptr` local filled by a call (returned by value, `lock()`), `if (p && p->ConstMethod())` reloads `px` for the method's `this` while the later non-const call reuses the first load; with a non-const method or a direct member access the loads are merged. `CUIManager::DispatchFocusedInput` matches with `pFocused->IsFocusable()` (a const `mFlags & 4` accessor, 98.6% to 100%). The same const-call reload explains the inlined `GetCurrentFrame` in the Matching `ScriptModel.cpp`, but the out-of-line CModel copy loads `mFlags` after `stwu`, which only a non-const method gives; making it non-const failed the DOL check, so it stays const (CModel copy at 90%). Making `TPartialAnm::IsIdle`/`IsReplaceable` const lowered QueueMotion, AppendMotion and Update.
- **Const and non-const `GetCurrentFrame` overloads were tried and rejected.** With both overloads, the CModel copy (`Fv`) matches. But every inlined caller through a non-const `shared_ptr` then selects the non-const overload, and `CPii::QueueMotion`, `CMultiRanking::Calc` and ScriptModel drop below 100%. ScriptModel only recovers through a `const CMotionProgram&` local. All inlined callers want the const body, so the single const accessor stays. The out-of-line call in `CModel::UpdateAnimations` probably goes to a different non-const method with the same body, whose name is unknown.
