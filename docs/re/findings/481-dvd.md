# Issue 481: DVD core state machine (`dvd.c`)

## F-481-1: Complete dvd.c unit

Target `wpse-v1`, frozen `config/targets/wpse-v1.json`. Evidence uses dtk 1.8.4 split objects, the Wii/1.0 compiler with `cflags_sdk` and default 16-byte function alignment, objdiff-cli 3.8.2 from `ninja`, and full DOL verification. The banner string at `0x803D6840` is `<< RVL_SDK - DVD \trelease build: Feb 27 2009 10:01:59 (0x4302_145) >>`. That is the same SDK build as zeldaret/tp `libs/revolution/dvd/dvd.c` at commit `c8fa8c9e2aab72cf4e5db0e5d1c84a9ea6ee6eb0` (CC0). That file is the primary structural reference. Petari `e0ab141914921726a595573dc48d3f13d0922efe` (CC0) `src/RVL_SDK/dvd/dvd.c` corroborated names and the restart-motor block.

`dvd.c` owns these ranges:

- `.text` `0x802D1A70`-`0x802D6694`, ending at the last function and leaving padding to `dvdqueue.c`.
- `.data` `0x803D6840`-`0x803D6C50`: the version string, two panic strings, `ImmCommand` and six switch tables.
- `.bss` `0x80454280`-`0x80458F30`.
- `.sdata` `0x804B8B90`-`0x804B8BA8`: `__DVDVersion`, the `"dvd.c"` file name and the low-memory pointer constants.
- `.sbss` `0x804B9720`-`0x804B97B8`.

The earlier #482 split covered only the three-function tail at `0x802D6660`; this issue replaces that fragment with the original unit.

All 53 target functions match; objdiff reports `.text`, `.data`, `.bss`, `.sdata` and `.sbss` at 100%. With the source linked as `Matching`, `ninja` exits 0 and `tools/verify/verify.py verify` passes for `main.dol`.

This revision differs from the tp source in these ways, each confirmed from target code or data:

- `DVDChangeDisk`, `DVDChangeDiskAsync`, `DVDCancelAll`, `DVDPrepareDisk`, `DVDPrepareDiskAsync`, `DVDCheckDisk`, `DVDCheckDiskAsync` and the two set-command helpers are absent, or the linker dead-stripped them. The source omits any whose strings or switch tables would otherwise remain in `.data`.
- `stateBusy` stamps commands 2, 3, 5, 13 through 16, 34, 37, 41 and 42. The tp list also includes 7 through 12; the original jump table at `0x803D6A14` sends those to the default label.
- `DVDReadAbsAsyncPrio` returns `BOOL` and takes an unsigned offset.
- The FST-size panic in the disk-change path is at line 1090 with the target's message.
- `__DVDResetWithNoSpinup` (`0x802D63A0`) follows `__DVDGetCoverStatus`.
- `__DVDLowBreak` sets `Breaking` and returns TRUE. It must be defined in this unit so it inlines into `DVDCancelAsync`.
- `__DVDStopMotorAsync` returns TRUE and `__DVDRestartMotor` is empty.
- The global `__DVDRestartMotorCommandBlock` (0x30) follows `__DVDStopMotorCommandBlock` in `.bss` at `0x80458F00`. Nothing references it, but omitting it shifts every later data section by 0x40.

## F-481-2: Broadway register accessor names

The function at `0x802D98B0` returns `diRegValCache[1]`, the cover register value, and the prepare routine at `0x802D98E0` issues IOS ioctl `0x7A` into the cover buffer. The routines at `0x802D9A50` and `0x802D9BC0` issue `0x95` and `0x96` into the buffers at `0x80459360` and `0x80459380`. The accessors at `0x802D98C0` and `0x802D98D0` return those buffers. These are the status and control registers, in the tp `dvd_broadway.c` order. #482 had named the four routines one position early. They are now:

- `DVDLowGetCoverRegister` (`0x802D98B0`)
- `DVDLowGetStatusRegister` (`0x802D98C0`)
- `DVDLowGetControlRegister` (`0x802D98D0`)
- `DVDLowPrepareCoverRegister` (`0x802D98E0`)
- `DVDLowPrepareStatusRegister` (`0x802D9A50`)
- `DVDLowPrepareControlRegister` (`0x802D9BC0`)

Consequently, `dvderror.c` reads the status register first. `__DVDStoreErrorCode` calls `DVDLowPrepareStatusRegister(cbForPrepareStatusRegister)`. That callback stores `DVDLowGetStatusRegister()` at `DVDErrorInfo` offset `0x10` and then prepares the control register. `cbForPrepareControlRegister` (`0x802D71C0`) stores the control register at `0x14`. The `DVDErrorInfo` members at `0x10` and `0x14` are renamed `status` and `control`; layout and code are unchanged and `dvderror.c` still matches.

Other renames: `DVDLowGetNoDiscBufferSizes`, `DVDLowGetNoDiscOpenPartitionParams`, `DVDLowStopMotor`, `DVDLowInquiry`, `DVDLowSetSpinupFlag`, `DVDLowReset`, `DVDLowAudioBufferConfig`, `DVDLowSetMaximumRotation`, `DVDLowRead`, `DVDLowSeek` and `DVDLowClearCoverInterrupt`. Each is named from its dvd.c call sites, which match the tp argument lists and call order. Only names changed; extents, types and splits stay with `dvd_broadway`.

## Traps

- **A 64-byte aligned buffer starts the unit's `.bss`.** `__DVDTicketViewBuffer` is followed by `__DVDTmdBuffer`, which needs `ATTRIBUTE_ALIGN(64)`; `BB2` and `CurrDiskID` need 32. Without these, `.bss` offsets drift even though every function scores 100%.
- **`ResetRequired` must be `volatile`.** With a plain declaration, its loads are scheduled differently from the target. `LastResetEnd` also stays volatile; making it non-volatile introduced new differences.
- **An unreferenced global still occupies `.bss`.** The target has a 0x30 gap at `0x80458F00` with no references. It is `__DVDRestartMotorCommandBlock`, and the linker keeps it. Dropping it made `.bss` 0x40 short, and verification failed at DOL header byte `0x7E`.
- **Switch tables are invisible to function comparison.** All functions scored OK while the `stateBusy` jump table pointed six entries at the wrong label. Verification found the first differing byte at file offset `0x3D2B32` (`.data` `0x803D6A32`).
- **`ninja` rewrites `dvd_broadway` data names.** After a build, dtk added local names such as `DiFD`, `dvdContexts` and `@3815` to `symbols.txt`, and changed sizes. Those changes are not part of this unit and were not committed.
