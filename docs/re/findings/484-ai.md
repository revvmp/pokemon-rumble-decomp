# F-484-1: AI boundary correction and AX initialization

Current status: F-484-2 below supersedes the original partial status. AI and AXAlloc are source linked; AX.c now passes complete object and source-linked frozen-DOL verification.

Target: `wpse-v1`, immutable `orig/wpse-v1/main.dol`. Issue #484 owns `.text` `0x802D9F30–0x802DA7BC`. This partial change reconstructs only the independent AX initialization unit at `0x802DA490–0x802DA500`; it leaves all remaining functions as original-object fallbacks.

## AI starts in issue #483

A scratch AI implementation based on CC0 Petari commit `e0ab141914921726a595573dc48d3f13d0922efe`, `src/RVL_SDK/ai/ai.c`, matched all ten AI function instruction sequences in #484 under Wii/1.0. A split-only build passed exact verification. However, attempting to link that source failed with an undefined `__AID_Callback` reference from `0x802D9EE0`, in #483.

Disassembly confirms `0x802D9EE0–0x802D9F24` is `AIRegisterDMACallback`: it reads the previous callback at `0x804B9838`, disables interrupts, stores the supplied callback, restores interrupts, and returns the previous callback. Thus the issue survey's DVD attribution for that last #483 function is wrong. The complete AI unit starts at `0x802D9EE0`, and its split is owned by #483. The attempted split and source were removed from the submitted change; #483 remains untouched.

AI data ownership: version string `0x803D84E8–0x803D8530`, version pointer `0x804B8BC8`, initializer flag `0x804B9800`, callback-active flag `0x804B9804`, five 64-bit timing values at `0x804B9808–0x804B9830`, saved stack `0x804B9830`, callback stack `0x804B9834`, callback `0x804B9838`. The stack-switch routine at `0x802DA250` is 100 bytes of original-style CodeWarrior assembly, not C reconstruction. The SDK banner is `Feb 27 2009 10:01:30 (0x4302_145)`.

The verified lesson is to inspect references immediately before an issue boundary before treating the first listed function as a translation-unit start. A split-only exact match does not prove source ownership or that static symbols stay inside the proposed unit.

## AX source and provenance

AX initialization follows [ogws AX.c](https://github.com/doldecomp/ogws/blob/f5a1bb5ed7692a9e09e737bc1236f592274dcf73/src/revolution/AX/AX.c), commit `f5a1bb5ed7692a9e09e737bc1236f592274dcf73`, licensed CC0-1.0 (repository license checked before reuse). The target has its extended initializer inlined into `AXInit` with output mode zero, plus a query of the initialization flag. `AXIsInit` is a descriptive SDK-style name supported by behavior, not an embedded symbol string. The other names follow the reference source. No comments or raw decompiler output were copied.

## F-484-2: AX initializer dependency and extent correction

The five external initializer names discussed in F-484-1 have since landed except the voice-parameter initializer. [ogws AXVPB.c](https://github.com/doldecomp/ogws/blob/f5a1bb5ed7692a9e09e737bc1236f592274dcf73/src/revolution/AX/AXVPB.c) names `__AXVPBInit`: it sets the maximum voices and three parameter/ITD/voice pointers, then calls `__AXVPBInitCommon`. The target at 802DD2A0 sets 96 voices, stores three corresponding static buffer addresses, and tail-calls 802DD2D0. The AXInit call sequence also agrees with the reference. Rename only `fn_802DD2A0` to `__AXVPBInit`, leaving its extent, types and split with #487. That callee still uses its original fallback; no new source coverage is claimed for it.

The existing AX source needs no instruction changes. Complete objdiff now shows its two function instruction streams at 100%. The earlier split incorrectly included four bytes of padding in each of `__AXVersion` and `__AXInitialized`; actual types are a four-byte pointer and a four-byte integer. The resulting data scores were 77.77779% and 50%, respectively. Correct both symbol sizes and end their sections at 804B8BD4 and 804B9844. The text ends at AXIsInit's return, 802DA4F8, leaving the eight bytes before AXAlloc to alignment.

The AX banner occupies 69 bytes at 803D8530; retain its .data split through 803D8578, including three bytes of alignment. Attempting an odd end of 803D8575 made dtk 1.8.4 reject the next automatic .data split's alignment. The source literal is unchanged, and no expected fingerprint is modified. These extents supersede the padded ownership table in F-484-1.

The complete AI unit merged in [PR #647](https://github.com/revvmp/pokemon-rumble-decomp/pull/647), with ownership and validation in [F-483-1](483-dvd-ai.md). AXAlloc's seven #484 functions already link from matching source, as recorded in [F-485-3](485-axaux.md#f-485-3-axalloc-completes-issue-485). With AX.c source-linked validation, these cover all nineteen #484 functions and 2,080 instruction bytes: ten AI functions, 1,320 bytes; two AX functions, 92 bytes; and seven AXAlloc functions, 668 bytes. AI includes one original-style 100-byte assembly stack switch, rather than a C reconstruction for that routine. Final acceptance is recorded below.

### Traps from the completion

The SDK pointer and int objects are four bytes even when the initial survey's anonymous storage label included trailing zeros. Compare declared object sizes separately from section alignment. Conversely, the odd-length AX banner cannot end an automatic .data split at an unaligned address in this configuration; retain its three alignment bytes. Neither case justifies changing a frozen hash or adding source padding fields.
