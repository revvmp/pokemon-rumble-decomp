# F-484-1: AI boundary correction and AX initialization

Target: `wpse-v1`, immutable `orig/wpse-v1/main.dol`. Issue #484 owns `.text` `0x802D9F30–0x802DA7BC`. This partial change reconstructs only the independent AX initialization unit at `0x802DA490–0x802DA500`; it leaves all remaining functions as original-object fallbacks.

## AI starts in issue #483

A scratch AI implementation based on CC0 Petari commit `e0ab141914921726a595573dc48d3f13d0922efe`, `src/RVL_SDK/ai/ai.c`, matched all ten AI function instruction sequences in #484 under Wii/1.0. A split-only build passed exact verification. However, attempting to link that source failed with an undefined `__AID_Callback` reference from `0x802D9EE0`, in #483.

Disassembly confirms `0x802D9EE0–0x802D9F24` is `AIRegisterDMACallback`: it reads the previous callback at `0x804B9838`, disables interrupts, stores the supplied callback, restores interrupts, and returns the previous callback. Thus the issue survey's DVD attribution for that last #483 function is wrong. The complete AI unit starts at `0x802D9EE0`, and its split is owned by #483. The attempted split and source were removed from the submitted change; #483 remains untouched.

AI data ownership: version string `0x803D84E8–0x803D8530`, version pointer `0x804B8BC8`, initializer flag `0x804B9800`, callback-active flag `0x804B9804`, five 64-bit timing values at `0x804B9808–0x804B9830`, saved stack `0x804B9830`, callback stack `0x804B9834`, callback `0x804B9838`. The stack-switch routine at `0x802DA250` is 100 bytes of original-style CodeWarrior assembly, not C reconstruction. The SDK banner is `Feb 27 2009 10:01:30 (0x4302_145)`.

The verified lesson is to inspect references immediately before an issue boundary before treating the first listed function as a translation-unit start. A split-only exact match does not prove source ownership or that static symbols stay inside the proposed unit.

## AX source and provenance

AX initialization follows [ogws AX.c](https://github.com/doldecomp/ogws/blob/f5a1bb5ed7692a9e09e737bc1236f592274dcf73/src/revolution/AX/AX.c), commit `f5a1bb5ed7692a9e09e737bc1236f592274dcf73`, licensed CC0-1.0 (repository license checked before reuse). The target has its extended initializer inlined into `AXInit` with output mode zero, plus a query of the initialization flag. `AXIsInit` is a descriptive SDK-style name supported by behavior, not an embedded symbol string. The other names follow the reference source. No comments or raw decompiler output were copied.

| Section | Range | Evidence |
| --- | --- | --- |
| `.text` | `0x802DA490–0x802DA500` | 0x54-byte initializer, 0x8-byte flag query, inter-function and trailing alignment |
| `.data` | `0x803D8530–0x803D8578` | 69-byte AX banner and alignment |
| `.sdata` | `0x804B8BD0–0x804B8BD8` | Four-byte `__AXVersion` pointer and trailing alignment |
| `.sbss` | `0x804B9840–0x804B9848` | Four-byte initialization flag and trailing alignment |

The exact AX banner reads `Feb 27 2009 10:01:36 (0x4302_145)`. AXInit first tests the flag, registers this banner, calls allocation/voice/sound/auxiliary/command-list/output initialization in reference order, then sets the flag. AXIsInit returns that same word. The unit contains 92 instruction bytes and 20 alignment bytes.

## Validation

Both compiled function extents match the original. Final commands and observed results are recorded in the pull request and ledger. No instruction mismatch remains. This is not a linked source match, and the unit deliberately remains NonMatching.
