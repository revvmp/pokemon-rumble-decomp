# Pokémon Rumble decompilation

A source reconstruction of Pokémon Rumble (WiiWare, USA, `WPSE`) that rebuilds the game's `main.dol` byte for byte.

![Roadmap progress](docs/images/progress-roadmap.svg)

![Code progress](docs/images/progress-code.svg)

All 13,462 CPU functions now match and link from source. Embedded DSP reconstruction and final acceptance are tracked separately in [progress](docs/PROGRESS.md). Images are generated by `tools/progress/progress.py`; see [progress images](docs/PROGRESS.md#progress-images).

## Setup

You need Windows 10 or 11 and access to this private repository. The original game files are already in `orig/`, so you do not need to provide them.

1. Install [Git](https://git-scm.com/download/win).
2. Install [Python](https://www.python.org/downloads/) 3.10 or newer. On the first installer screen, tick **Add python.exe to PATH**.
3. Open a terminal and clone the repository:

   ```
   git clone https://github.com/revvmp/pokemon-rumble-decomp.git
   cd pokemon-rumble-decomp
   ```

4. Run the build:

   ```
   .\build.bat
   ```

   This works in both PowerShell and Command Prompt.

   The first run downloads the pinned compilers and tools into `tools/local/` and checks each one's digest. It then builds the game and compares the result with the original.
5. The last line should read `Build succeeded: build\wpse-v1\main.dol matches the original.` Run `.\build.bat` again after every change.

If a step fails, see the [setup guide](docs/SETUP.md) for the commands `build.bat` runs and what each one checks.

## Contributing

Work is split into GitHub issues, each owning a block of functions; see [workstreams](docs/WORKSTREAMS.md).

1. Install the [GitHub CLI](https://cli.github.com/) and sign in with `gh auth login`.
2. Read [collaboration](docs/COLLABORATION.md).
3. To work with an LLM agent such as Claude Code, open it in the repository and say "take an issue". It claims an unassigned issue and follows the current main-branch workflow: agents own separate files and scratch outputs while one coordinator runs the shared build and verification. See root `AGENTS.md` for the rules agents follow.

Start with the [documentation index](docs/README.md) and [architecture](docs/ARCHITECTURE.md). All project documentation lives in `docs/`; reverse engineering documentation lives in `docs/re/`. No unit tests or code comments are permitted; see [project rules](docs/PROJECT_RULES.md) and [current progress](docs/PROGRESS.md).
